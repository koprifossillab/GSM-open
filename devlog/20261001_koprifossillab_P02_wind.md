# 바람을 온 지구 화면에서 흐르게 (계획)

2026-10-01 · `main` · koprifossillab

[docs/바람_시각화.md](../docs/바람_시각화.md) 의 검토를 사람이 이렇게 정했다 — **"지난 바람과 지금의 바람 모두. 디폴트는 지금의
바람. 높이도 둘 다. 디폴트는 10 m, 사용자 선택으로 제트기류도. 기간은 이야기한 대로(2005-06 ~ 2007-12), 바람 먼저."**
이어서 "numpy 설치하면 되지", "cron 으로 받아야 하는 거면 호스트에서 처리해도 돼".

## 1. 정한 것

| | 지금의 바람 (기본) | 지난 바람 |
|---|---|---|
| 자료 | NOAA GFS 0.25° 분석(f000) — 가장 새 판 | ECMWF ERA5 0.25° — ARCO-ERA5(Google Cloud 공개 버킷) |
| 시각 | 하루 네 번(00·06·12·18 UTC). 최근 여덟 판(이틀)만 둔다 — 예보는 다음 판이 이긴다 | 2005-06-01 ~ 2007-12-31, **날마다 00 UTC** — 940 시점 남짓 |
| 높이 | **10 m(기본)** · 250 hPa(제트기류) | 같다 |
| 받는 길 | NOMADS grib filter 로 u·v 두 높이만, 한 판에 한 번(3 MB 남짓) | 10 m 는 덩이 통째(성분마다 3.3 MB), 250 hPa 는 37 층 덩이에서 **그 층의 블록만 HTTP Range 로**(성분마다 3 MB 남짓) |
| 푸는 것 | ecCodes(GRIB2) | numcodecs(blosc-lz4) |
| 언제 | **호스트 cron, 매시 :35** — 새 판이 없으면 아무것도 하지 않는다 | 사람이 명령을 한 번 부른다 |
| 조건 | 미국 정부 자료 — 제한 없음 | CC BY 4.0 — "Contains modified Copernicus Climate Change Service information" |

## 2. 받고 굽는 것은 호스트에서, 내주는 것은 컨테이너가

- **numpy·ecCodes·numcodecs 는 호스트 venv(`~/venv/GSM`)에만** 깐다(`requirements-wind.txt`). ecCodes 는 eckit 까지 45 MB 라 운영
  이미지에 넣지 않는다 — 이미지는 그대로 Django·Pillow·requests 다. 컨테이너는 구워 둔 PNG 와 JSON 을 내주기만 한다
- 명령은 저장소의 `manage.py` 다(`fetch_gfs_wind`·`build_era5_wind`). 호스트에서 `GSM_DB_PATH=/srv/GSM/db/GSM.db` 로 부르면
  `<DB 옆>/wind/` 에 쓴다. DB 는 건드리지 않는다
- **문 둘** — `gfs.py`(NOAA NOMADS)와 `era5.py`(Google Cloud). `requests` 를 쓰는 자리가 열셋에서 열다섯이 된다. 화면이 부를 때는
  상류를 타지 않는다
- **굽는 꼴** — 시점·높이마다 PNG 한 장(1440×721, 경도 −180→180, 위도 90→−90), R=u·G=v 를 그 장의 최솟값·최댓값으로 0–255 에
  담는다. 되돌릴 값은 그 출처의 `index.json` 에. 화면이 경도 0 부터의 원본을 다시 돌리지 않게 굽는 쪽이 돌린다
- 자리 — `<DB 옆>/wind/gfs/<YYYYMMDDHH>/{10m,250hPa}.png`, `<DB 옆>/wind/era5/<YYYYMMDD>/…`, 출처마다 `index.json`.
  새로 쓴 것은 옆 자리(`.part`)에 다 쓴 뒤 바꿔 끼운다 — 굽는 동안에도 뷰어는 옛것을 낸다
- 주소 — `earth/wind/` (두 출처의 목록), `earth/wind/<출처>/<시각>/<높이>.png`. 한 번 구운 PNG 는 바뀌지 않으므로 오래 캐시하게 한다
- **백업** — `wind/gfs/` 는 여섯 시간마다 바뀌므로 주간 백업의 "구운 것" 목록에서 뺀다(넣으면 매주 1.4 GB 를 새로 뜬다). `wind/era5/`
  는 한 번 구우면 그대로라 "구운 것" 에 든다

## 3. 화면

- 온 지구 화면의 레이어 목록에 **"바람"** 레이어군 하나. 오늘의 레이어다(1 Ma 부터의 그때의 지구에는 뜨지 않는다)
- 카드에 고르개 셋 — **지금/지난**, **10 m / 250 hPa(제트기류)**, 지난이면 날짜와 재생
- **입자는 Canvas 2D 로 그린다** — 경위도로 입자를 옮기고, 화면 자리는 평면이면 OpenLayers 가(4326·3413·3031 모두), 구면 Cesium
  이 셈한다. 한 벌의 코드가 세 평면과 구를 다 덮는다. WebGL 셰이더는 입자 수가 모자랄 때 다시 본다
- 색은 빠르기. 지난 바람의 재생은 날짜 사이를 섞어 매끄럽게
- 출처 줄 — GFS 는 "NOAA/NCEP GFS", ERA5 는 Copernicus 문구. 화면의 글은 영어도 같은 커밋에

## 4. 단계

1. **받기·굽기·내주기** — 문 둘, 명령 둘, 주소 둘, 호스트 venv·cron, 백업 목록. 시험
2. **화면** — 바람 레이어, 입자, 고르개, 영어판
3. **지난 바람 940 시점을 굽고 배포**

단계마다 브랜치·PR·devlog 하나.

## 5. 버린 것

- **이미지에 numpy·ecCodes** — 45 MB 남짓을 운영에 들일 까닭이 없다. 받는 일은 cron 이 하고, cron 은 호스트에서 돈다
- **GRIB2 디코더를 직접 짜기** — GFS 바람은 한 꼴(template 5.3)뿐이라 100 줄이면 되지만, ecCodes 를 호스트에 둘 수 있으니 짤 까닭이 없다
- **ERA5 를 Copernicus CDS 로** — 계정·키가 들고 요청이 줄을 선다. ARCO 는 Range 로 층을 잘라 받을 수 있어 CDS 의 장점이 사라졌다
- **ERA5 를 하루 평균으로** — 24 시각을 받아야 한다. 00 UTC 한 시각이면 GFS 와 같은 "그 순간의 바람" 이다
- **WebGL 셰이더부터** — 세 투영과 구를 따로 짜야 한다. Canvas 2D 로 수천 입자면 먼저 보이기에 충분하다
