# 브라우저 캐시 — 모든 응답에 ETag·304, 판이 든 주소만 길게

2026-10-02 · `feature/tile-cache-headers` · wetherilli

없어, 하루가 지나면 같은 그림을 통째로 다시 받는다.

## 1. ETag·304 — 미들웨어 한 줄

`django.middleware.http.ConditionalGetMiddleware` 를 붙였다. 200 응답의 본문으로 ETag(md5)를 달고, 브라우저가 `If-None-Match` 로
되물으면 본문 없이 304 를 낸다.

- **뷰마다 ETag 를 짓지 않았다.** 타일을 내는 길이 `_tile` 하나가 아니다 — `wms`·`legend`·상류마다의 z/x/y·달·화성·온 지구의 타일까지
  `Cache-Control` 을 적는 자리가 스무 곳이 넘는다. 하나라도 빠뜨리면 그 상류만 다시 받는다. 미들웨어는 빠뜨릴 수가 없다
- **안내 타일은 그대로다.** 미들웨어가 `no-store` 에는 ETag 를 달지 않는다 — "인증키가 없다" 를 브라우저가 붙들 일이 없다(시험)
- 값: 304 를 내려 해도 서버는 응답을 다 지어 본다(캐시에서 꺼내거나 그린다). 아끼는 것은 보내는 바이트다 — 타일 한 장 60 KB 가 0 이 된다.
  캐시에 든 것은 꺼내는 값이 작다
- nginx 가 gzip 을 걸면 ETag 가 약한 것(`W/`)이 되는데, Django 는 약하게 견주므로 304 는 그대로 난다

## 2. 길게(immutable) — 판이 주소에 든 것만

우리가 굽는 타일은 판(`RENDERER`·자료의 판)이 바뀌기 전에는 같은 그림이라 오래 들고 있어도 된다. 그러나 **주소가 그대로면** 판이 바뀌어도
브라우저가 1 년 동안 옛 그림을 붙든다. 그래서 주소에 판을 넣은 것만 길게 한다.

- 카탈로그가 주소를 주는 셋 — GeoMAP(`?v=<자료의 판>r<RENDERER>`, 캐시 열쇠와 같은 둘), IBCSO 자료 출처·음영판(미리 잘라 둔 폴더의 고친 때.
  `build_*` 가 새 폴더를 만들어 바꿔 끼우므로 다시 구우면 바뀐다)
- 뷰는 **주소의 판이 지금 판과 같을 때만** `public, max-age=31536000, immutable` 을 단다(`views._immutable`). 판이 없거나 옛 판이면 —
  옛 화면이 열린 채 판이 올랐다 — 지금 그림을 하루짜리로 낸다. 옛 주소에 새 그림을 1 년 묶지 않는다
- 파일이 없어 판을 모르면 주소에 `?v=` 를 붙이지 않는다 — 빈 판으로 길게 둘 일이 없다
- **상류에서 받은 것은 길게 두지 않는다.** 상류가 판을 올려도 우리는 알 길이 없다(CLAUDE.md "새 것이 이긴다"). `?v=` 를 붙여 불러도 하루다(시험)

## 3. 남긴 것

판이 열쇠에 든 우리 타일은 서른 곳 가까이 되지만 대부분 **JS 가 주소를 짓는다** — 달·화성·수성 원도, 온 지구의 판 회전·옛 해안선·화석·화산·
지진·지각·지명, IBCSO 배경(bed·ice). 거기에 판을 넣으려면 판을 화면에 알리는 길(카탈로그 값이나 페이지에 박는 값)부터 내고 JS 다섯 파일을
고쳐야 한다. 그 파일들을 지금 다른 세션들이 고치고 있어 이번에는 하지 않았다. ETag 가 붙었으니 그것들도 하루 뒤에는 304 로 되묻는다 —
잃는 것은 하루에 한 번 되묻는 왕복뿐이다. TODOs 에 남겼다.

`TILE_IMMUTABLE_SECONDS`(기본 1 년, `GSM_TILE_IMMUTABLE_SECONDS`)를 0 으로 두면 길게 두기를 끈다.
