# 정적 판의 영어판과 소개 — 말마다 따로 굽고, 뿌리는 소개로

2026-10-02 · `feature/static-lang-intro` · wetherilli

정적 판(162)은 한국어 지도 한 장만 굽고 뿌리를 지도로 넘겼다. 영어판이 없었고, 소개는 "서버의 것을 많이 써서" 두지 않았다.

## 1. 영어판 — `en/` 에 한 번 더 그린다

서버는 쿠키(`gsm_lang`)·Accept-Language 로 말을 고르고 틀을 그 말로 그린다. 정적 판에는 쿠키를 읽을 서버가 없으니 **말마다 따로
굽는다** — `deploy/static_site.py` 가 지도와 소개를 한국어·영어로 한 번씩, 네 장을 그린다. 한국어는 뿌리·`map/`, 영어는 `en/`·`en/map/`.
정적 파일은 한 벌이라 `/GSM/static/` 은 앞머리로만 바꾸고, 그 밖의 주소(소개↔지도)는 영어판이면 `en/` 밑으로 바꾼다.

- **말 바꾸기** — 정적 판이면 쿠키 대신 그 말의 장으로 간다. 지도에서는 보던 자리(`?`·`#` 꼬리)를 그대로 넘긴다. 고른 말은
  `localStorage`(`gsm.lang`)에 남긴다
- **처음 오는 사람** — 서버처럼, 고른 말이 없고 브라우저가 한국어를 받지 않으며 영어를 받으면 뿌리에서 `en/` 으로 넘긴다
- **`BASE` 셈** — map.js 는 `…/map/` 을 떼어 뿌리를 셌다. 이제 `…/en/map/` 도 떼야 한다 — 구운 타일·점(`baked/`)은 말과 상관없이
  뿌리에 한 벌이다. 앞의 `/` 까지 보고 뗀다: 처음에 `en\/$` 로 떼었다가 **`/GSM-open/` 도 끝이 `en/` 이라** 뿌리가 `/GSM-op` 이
  되는 것을 브라우저로 보고 고쳤다
- **버린 것:** 화면에서 말을 바꾸기(JS 가 `T()` 로 다시 그리기) — 틀의 글은 서버(`{% t %}`)가 그리므로 화면만으로는 반쪽이다.
  장을 두 벌 굽는 것이 서버와 같은 길이고 크기도 HTML 몇 장뿐이다

## 2. 소개 — 정적 판에 맞게 빼고 뿌리에

소개 템플릿이 `static_site` 를 받아 **서버가 있어야 하는 것**을 그리지 않는다 — 3D 장면, 우주(달·화성·수성) 장면, 시작 탭의
3D·온 지구 문과 우주 갈래, 장면 차례의 "3D"·"우주". 서버 판은 그대로다.

**지역은 화면이 거른다**(`intro.js`) — 실린 지역은 굽는 때(`--baked`)마다 달라 템플릿이 아니라 `static-config` 를 읽는다.
실리지 않은 지역의 문은 감추고(`[hidden]` — `.door` 의 `display` 가 이기지 않게 CSS 한 줄), 그 지역의 장면이 가리키던 "지도로 바로
가기" 는 한국 지도로 돌린다. 극지 장면은 남긴다 — 무엇을 하는 뷰어인지 보이는 장면이고, 구운 극지가 실리면 그대로 이어진다.
묶음(북극·동아시아)은 품은 지역이 **둘 이상** 실려야 문을 세운다 — 한국 하나뿐인 동아시아는 한국 지도와 같은데 "한국과 일본을
한 화면에" 라고 적힌다. 품은 지역은 map.js 의 `REGIONS.*.includes` 를 옮겨 적었다(둘이 어긋나면 문 하나가 덜 서거나 더 설 뿐이다).

소스 링크(AGPL 13조)는 바닥글에 이미 있다(`SOURCE_URL`, GSM-open 의 판마다 사본, 149).

## 3. 확인한 것

- 시험 — 정적 소개(한국어·영어)에 3D·온 지구·달·화성·수성으로 가는 문·장면이 없고 `static-config` 가 실리는지, 서버 판은 그대로인지
- 이 기계에서 구워 `/GSM-open/` 꼴로 띄워(확인한 뒤 지웠다): 뿌리가 소개, English → `en/`(영어 소개), `en/map/` 영어 지도,
  거기서 한국어 → `map/`, `en-US` 브라우저로 뿌리를 열면 `en/` 으로. 시작 탭에는 한국 문만. 페이지 오류 없음
