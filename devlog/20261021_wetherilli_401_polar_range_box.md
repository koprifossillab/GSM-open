# 극지 화면의 범위잡기를 경위도 네모로

2026-10-21 · `fix/polar-range-box` · wetherilli

사용자 — 「영역 도구를 쓰면 직사각형이 잡히는데 … 극지 지역에서는 극지에 가까울 때 그거에 따른 왜곡이 크잖아」.

## 무엇이 틀렸나

지역 지도(`map.js`)의 범위잡기는 **끈 화면 네모를 그대로** 범위로 두었다. 3857 에서는 화면 네모가 곧 경위도 네모라
상관없지만, 극 평사도법(3413·3031)과 캐나다 람베르트(3978)에서는 아니다. 그래서 꼭짓점을 동서남북으로 못 불러
"왼쪽 위 …" 로 불렀고, 수치가 서로 맞지 않았다 — 남극점을 품게 끌면 넓이는 5 206 km² 인데 가로 × 세로는
1 104 × 1 103 km 였다(꼭짓점 넷을 대권으로 이은 면을 쟀기 때문이다). 극 밖에서도 위아래 변이 위선이 아니라
"이 범위" 를 경위도로 적어 둘 수 없었다.

구 화면(달·화성·수성·온 지구)은 처음부터 범위를 경위도 네모(`w·s·e·n`)로 두었다. 다만 극 평면에서 끈 네모의
**왼쪽 아래·오른쪽 위 귀**를 경위도로 바꿔 네모를 잡아서, 극 평면에서는 엉뚱한 네모가 나왔다.

## 어떻게 했나

다섯 화면을 한 틀로 맞췄다 — **끈 시작점과 끝점의 경위도로 경위도 네모를 잡는다.** 경도는 짧은 쪽으로 잇는다.
끈 화면 네모가 **극을 품으면** 그 네 귀를 다 덮는 극 모자(경도 360°, 경계 위선 하나)다 — 극을 품는 경위도 네모는
달리 정할 길이 없다. 모자의 "중앙" 은 극이다.

- 지역 지도의 범위는 이제 `box` 를 들고, 그림·수치·저장·투영 바꾸기가 다 거기서 나온다. 투영을 바꿀 때는
  `_ll`(위경도 고리)에서 옮긴다 — 화면 네모를 옮기던 때처럼 꼭짓점 넷만 옮겨지지 않는다
- 넓이는 구면 띠 공식(`R² · Δλ · (sin φn − sin φs)`, 반지름은 `ol.sphere` 의 것), 가로는 가운데 위선의 길이 —
  구 화면과 같은 셈이다. 전에는 가로를 가운데 위도의 두 점 사이 대권 거리로 쟀는데, 우리나라 크기에서는 차이가 없다
- **끄는 동안에도 경위도 네모를 그린다.** DragBox 의 CSS 네모(`range-box`)를 그대로 두면 끄는 동안의 네모와 손을
  뗀 뒤의 휜 네모가 달라 보인다. 그래서 DragBox 에는 모양 없는 이름(`range-ghost`)을 주고, `boxdrag` 마다 지도에
  그린다. 3857·등거리 원통에서도 같은 길로 가서 화면마다 갈래를 두지 않았다. 안 쓰게 된 `.range-box` CSS 는 지웠다
- 위아래 변은 1°(구 화면은 2°)마다 찍어 위선을 따른다
- 극 모자를 올리는 GeoJSON 은 경위도 평면에서 극을 품도록 극의 변으로 닫는다. 화면에서는 경계 위선 하나로 그린다 —
  극의 변까지 두면 극 평면에서 가운데로 가는 선이 보이고, Cesium 의 면이 갈라진다

## 버린 것

- **화면 네모를 두고 이름만 바로잡기** — 꼭짓점 이름과 넓이만 고치면 작지만, 사용자가 말한 "왜곡" 은 범위가 경위도와
  어긋나는 것 자체다. 시료 권역·조사 범위로 적어 두는 자리라 경위도 네모여야 쓸 수 있다
- **극 모자 대신 극을 품는 끌기를 막기** — 남극 탭은 남극점이 가운데라 극을 품는 범위를 자주 잡는다

## 시험

`test_mobile.PolarRange` — 남극 탭에서 극을 품게 끌면 중앙이 −90° 이고, 극 밖에서 끌면 위아래 귀의 위도·좌우 귀의
경도가 같다. 옛 코드로 돌리면 깨지는 것을 보았다. 시험을 짜다가 도구 단추가 두 번째 누름에 꺼져 둘째 끌기가
지도를 끌기만 하고도 통과하는 것을 알았다 — 켜져 있으면 누르지 않는다.
