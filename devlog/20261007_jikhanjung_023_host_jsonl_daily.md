# 호스트의 jsonl 을 날마다 나눈다

2026-10-07 · `feature/host-jsonl-daily` · jikhanjung

호스트는 `GSM.db` 를 열지 않는다(jikhanjung 016) — 손으로 부른 일의 기록은 `fetch_log_host.jsonl`, 상류 호출 수는 `upstream_host.jsonl` 에
덧붙이고 컨테이너가 매시 들인다. 들인 뒤에도 파일은 남아 끝없이 자랐다(첫 차례 888 바이트 — 한 해 8 MB 남짓, jikhanjung 018 의 TODOs).

## 1. 무엇을 정했나

1. **날마다 한 파일** — `<DB 옆>/fetch_log_host/<YYYYMMDD>.jsonl`·`<DB 옆>/upstream_host/<YYYYMMDD>.jsonl`. 날짜는 이 서버의 날(`localdate`)
2. **다 들인 지난 날의 파일은 컨테이너가 지운다** — 읽은 자리(`FetchRunMark` 의 `<폴더>/<날짜>`)가 파일 끝이고, **그제 것부터**. 어제 것은
   자정을 넘겨 도는 일이 아직 덧붙일 수 있어 둔다. 지우면 그 자리 표지도 지운다
3. **지우기는 커밋 뒤에**(`transaction.on_commit`) — 들이다 깨지면(잠금 따위) 읽은 자리가 되돌아가는데 파일을 먼저 지우면 그 줄이 사라진다.
   시험에서 깨진 들이기 뒤에 파일이 남고 다음에 다시 들이는 것을 본다
4. **옛 한 파일**(`fetch_log_host.jsonl`·`upstream_host.jsonl`)도 다 들일 때까지 읽고, 하루 넘게 손대지 않은 뒤 지운다 — 운영에 이미 있다
5. **폴더는 무리가 쓰게**(2775, setgid) — 호스트가 만들고 컨테이너가 지운다. 지우지 못하면 남기고 적는다(읽은 자리가 있어 두 번 들이지 않는다)
6. 주간 백업 — `upstream_host/` 는 빼는 목록, `fetch_log_host/` 는 ① 에(옛 한 파일과 같은 대접)

## 2. 버린 것

- **컨테이너가 다 읽은 뒤 파일을 비우기(truncate)** — 그 사이 호스트가 덧붙인 줄이 사라질 수 있다. 날마다 나누면 이어 붙이는 쪽과 지우는 쪽이
  같은 파일을 두고 겨루지 않는다
- **이름을 바꿔 돌리기(rotate)** — 덧붙이는 중인 파일을 옮기는 겨룸이 남는다

## 3. 확인

- 시험 — 그제 것은 지우고 어제·오늘 것은 둔다(자리 표지도), 깨진 들이기 뒤에 파일·자리가 남고 다음에 들인다, 옛 한 파일도 다 들이고 지운다,
  상류 호출 수도 날마다, 백업의 목록. 전체 통과
- 운영 사본으로 호스트 방식의 한 차례(`fetch_recent_quakes`) → 컨테이너의 `sources_log --sync-only` — 날마다의 파일 둘(폴더 2775·파일 664),
  기록 한 줄과 호출 수가 들어가고 날마다의 읽은 자리가 생겼다
