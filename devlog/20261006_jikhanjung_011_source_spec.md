# 자료원 명세 — `sources.json` 과 씨앗 (P02 1 단계)

2026-10-06 · `feature/source-spec` · jikhanjung

jikhanjung P02 의 1 단계. 받아 두는 자료원마다 사람이 정하는 것(조건·주기·돌리는 곳·명령·산출물)을 `<DB 옆>/sources.json` 한 장에
적고, 그것을 읽고 검사하는 `viewer/sources.py` 를 세웠다. 기록 표(2 단계)와 화면(3 단계)이 이것을 읽는다.

## 1. 무엇을 정했나

1. **씨앗은 저장소, 운영 판은 `<DB 옆>`** (사람이 `<DB 옆>` 을 골랐다). 컨테이너가 뜰 때 `manage.py sources_seed` 가 운영 판이 없으면
   씨앗을 옮겨 놓고, 있으면 **씨앗에만 있는 id 를 끝에 덧붙이기만** 한다. 같은 id 가 다르면 덮지 않고 이름만 알린다 — 사람이 서버에서
   고친 조건을 판을 올릴 때마다 되돌리면 고칠 마음이 안 난다(`seed_catalog` 가 손질한 제목을 지키는 것과 같은 까닭)
2. **운영 판이 깨져 있으면 씨앗으로 덮지 않는다** — 사람이 고치다 만 파일일 수 있다. 읽기는 마지막으로 떠 둔 판으로 버틴다
3. **이력은 읽을 때 뜬다** — sha256 이 앞서 떠 둔 판과 다르면 `sources_history/<날짜-시각>-<sha 앞 12>.json` 으로. 관리 화면에 계정이
   없어 명세는 서버에서 손으로 고치므로, "언제 무엇이 바뀌었나" 를 남길 자리가 이것뿐이다. 기록 표에 `_spec` 한 줄을 남기는 것은 2 단계에서
4. **틀린 줄은 건너뛴다** — 칸이 틀리거나 빠진 줄, 겹친 id 는 빼고 까닭을 `problems` 에 적는다(영어판도 있다 — 3 단계 화면이 띄운다).
   파일째 못 읽으면 떠 둔 판을, 그것도 없으면 빈 명세. **뷰어는 멈추지 않는다**
5. **이름은 두 말로 칸에 적는다**(`name.ko`·`name.en`) — 자료라서 `i18n` 표를 거치지 않는다. 시험이 영어 이름에 한글이 섞이지 않았는지 본다
6. **씨앗이 코드와 어긋나면 시험이 깨진다**(`sources.coverage`) — 모든 `fetch_*`·`build_*` 명령(45)이 어느 자료원의 `commands` 에,
   모든 `datastatus.ITEMS` 의 열쇠가 어느 자료원의 `outputs` 에 든다. 연구실 내부용 표시(`lab_only`)가 `datastatus` 의 `lab` 과 같다.
   새 명령을 더하는 사람이 씨앗에 한 줄 적게 하려는 것이다
7. 명령이 없는 자료원(GeoMAP·얀마옌·geo3al·SPA 처럼 사람이 파일을 두는 것)은 `kind: file` 로 둔다 — 장부에는 올라야 한다

## 2. 씨앗 49 곳

`docs/외부_자료원.md` 의 1·2, `datastatus.ITEMS`, `docs/상류_조건표.md`, `hourly.sh`·`weekly_backup.sh`, 명령마다의 머리글에서 옮겼다.

- `fetch` 16 · `build` 28 · `file` 4 · `once` 1. 돌리는 곳은 호스트 6(바람·구름·아라온호·최근 지진·ERA5·ECCO2), 컨테이너 13, 사람 30
- 주기 — 매시 4(GFS·GMGSI·아라온호·최근 지진), 매주 1(극지연구소), 매달 첫 월요일 1(PBDB), 한 번 1(대만), 나머지 사람이

- 결과를 저장소 `data/` 에 굽는 것(지각 두께·GLiM·판 경계·지명 따위)은 `outputs` 에 `data/…` 로 적었다 — `datastatus` 밖이다

## 3. 버린 것

- **씨앗을 늘 덮어쓰기** — 판을 올릴 때마다 사람이 고친 조건이 되돌아간다
- **명세를 Django 모델로** — 사람이 정하는 것을 바꾸는 데 마이그레이션·PR 을 거치게 된다(검토의 "명세는 JSON 으로")
- **지금 있는 파이썬 표를 옮기기** — `datastatus.ITEMS`·`static_site.UPSTREAMS`·`views.LAB_ONLY`·`NO_STORE` 는 그대로. 어긋나면 시험이 알린다
- 이력을 git 처럼 저장소에 — 운영 판은 서버에 있고 서버에는 저장소가 없다(배포는 이미지로)

## 4. 운영에 닿는 것

- `entrypoint-web.sh` — `seed_catalog` 뒤에 `sources_seed`. 실패해도 화면은 뜬다
- `weekly_backup.sh` — `sources.json`·`sources_history/` 를 "다시 못 얻는 것" 으로 담는다
- `.gitignore`·`.dockerignore` — 개발 장비의 `<DB 옆>` 은 저장소 뿌리라 운영 판이 거기 생긴다. 커밋·이미지에 들지 않게
