# 해저 — GEBCO 해저 지형 배경, EMODnet 해저 지질

2026-10-02 · `feature/seafloor-gebco-emodnet` · wetherilli

TODOs "온 지구" 의 둘째 줄이다(후보 견줌은 `docs/새_상류_후보.md` §1). 바다 밑을 두 겹으로 넣었다 — 온 바다의 **지형**은
GEBCO 를 배경으로, 북극 바다의 **지질**은 EMODnet 을 레이어로.

## 1. 이용 조건

- **GEBCO** — "The GEBCO Grid is placed in the public domain and may be used free of charge"(gebco.net, 격자 안내). 출처를 밝히고,
  공식 승인처럼 보이게 쓰지 않는다. 인용 꼴은 `GEBCO Compilation Group (2026) GEBCO 2026 Grid (doi:10.5285/4f68d5c7-45eb-f999-e063-7086abc036fa)`.
  WMS 의 AccessConstraints 는 "항해·해상 안전에 쓰지 않는다" — 배경 설명(`note`)에 적었다
- **EMODnet** — EMODnet 이 만든 자료는 EU 소유, CC BY 4.0. 출처 문구 "This data product was created by EMODnet … licensed under
  CC BY 4.0"(EMODnet 이용 조건). WMS 의 AccessConstraints 는 보증하지 않는다는 말뿐이다. 레이어의 `attribution` 에 EMODnet Geology
  와 CC BY 4.0 을 단다. 둘 다 밖에 열어도 걸리는 것이 없다

## 2. GEBCO 는 문을 내지 않고 배경으로

처음 맡을 때는 `gebco.py` 문과 씨앗 레이어를 그렸다. 사용자와 정해 바꿨다.

- **땅까지 칠한 불투명한 그림이다.** 레이어로 두면 지질도 위·아래 어디에 얹어도 하나를 가린다. IBCSO(071)도 같은 까닭으로 배경이다
- **레이어명 하나는 지역 하나에만 걸린다**(`Layer.name` 이 유일하다). GEBCO 는 모든 지역이 쓸 것이라 레이어로는 맞지 않는다
- 열쇠가 없고 CORS 가 `*` 다 — 극지 배경(017)처럼 브라우저가 곧장 부를 조건이 된다. 서버 캐시에 담는 것은 TODOs "캐시" 의
  "곧장 받는 배경 가운데 조건이 허락하는 것을 서버에 담는다" 의 몫이다 — 공공 도메인이라 그때 첫째 후보다

배경은 둘이다 — `GEBCO_LATEST`(음영, 모든 지역)와 `GEBCO_LATEST_SUB_ICE_TOPO`(얼음 밑, 그린란드·남극). `GEBCO_LATEST_2`(색만,
음영 없음)는 지질도 밑에서 밋밋하고, `_3` 은 잰 곳만 칠한 판이라 배경이 아니다. 상류가 **3857·4326 만** 그려서 극 평사도법 탭은
4326 을 받아 OpenLayers 가 옮겨 그린다 — 3857 은 극에서 끊긴다. 한 장에 2 초 남짓 걸리고 격자가 15″(약 450 m)라 줌 9 위로는
묻지 않고 늘린다.

온 지구 화면에도 배경으로 더했다. 구는 Cesium 의 WMS 로 곧장 받는다. **평면의 극 평사도법에서는 Blue Marble 로 갈음한다** —
평면 배경은 영상 보정 셰이더(042)를 거치는 WebGL 타일이라 옮겨 그리지 못하고, GEBCO 는 3413·3031 을 주지 않는다.

## 3. EMODnet — 북극해에 두고 스발바르가 빌린다

- 문 `emodnet.py`, 상류 이름 `emodnet`. GeoServer WMS 다. CORS 가 열려 있지만 **문을 거친다** — 속성을 추리고(열이 마흔 남짓,
  담당자 메일까지 온다) 캐시에 담는다
- **3413 으로 곧장 받는다.** GetCapabilities 는 3413 을 적지 않지만 GeoServer 가 그려 준다(2026-10-02 확인). 3857 로 물으면 북위
  78° 에서 축척이 다섯 배 부풀어(NPI 021 의 함정과 같다) 축척 따라 판을 고르는 퇴적물(multiscale)이 거친 판을 낸다
- 레이어명에 `emodnet:` 를 붙였다 — 상류 이름에 제 접두사(`bgr:`·`gtk:`)가 있는 것이 섞여, 다른 상류와 부딪히지 않게. 문이 뗀다

**어느 지역에.** 스발바르·얀마옌 둘레 바다를 보려던 것이다. 사용자가 "북극해에 두고 북극·북극해·스발바르에 얹자" 고 했다.

- 지역은 `arctic_ocean`. 북극 묶음은 `includes` 로 저절로 품는다
- **스발바르 탭은 빌린다** — `REGIONS.svalbard.borrow = { arctic_ocean: ["emodnet"] }`, `regionCatalog()` 가 그 지역의 레이어군
  가운데 그 상류의 것을 끝에 붙인다. 스발바르를 묶음(`includes`)으로 바꾸면 KPDC 의 북극해 자료(아라온 항적·관측소)까지 따라오고,
  "준비 중"·지역 머리말·추가 지역 목록의 들여 세우기(wetherilli 111)가 다 묶음으로 돈다. 상류 하나만 빌리는 편이 좁다
- 얀마옌 탭은 빌리지 않았다 — 얀마옌 둘레는 제4기 이전 지질도 현무암 한 면이고 퇴적물은 4 % 만 덮는다. 북극 묶음에서 보인다

**어느 레이어를.** 스발바르(0–40°E, 74–82°N)·얀마옌(14–2°W, 69–73°N) 네모에서 레이어마다 한 장씩 받아 덮는 몫을 쟀다.

| 레이어 | 스발바르 | 얀마옌 | |
|---|---|---|---|
| 제4기 이전 지질 — 암상·시대 | 77 % | 100 % | 넣음 |
| 해저 퇴적물 Folk 7 | 41 % | 4 % | 넣음 (5·16 갈래는 같은 면이라 7 하나) |
| 제4기 이전 단층 | 6 % | 3 % | 넣음 (선이라 몫이 작다) |
| 제4기 퇴적층 암상 | 13 % | 4 % | 뺌 — 그 자리에서 속성이 비었다 |
| 지질 사건 25만 | 8 % | 91 % | 뺌 — 얀마옌 둘레는 한 갈래의 넓은 면뿐 |
| 해저 침식 | 2 % | 0 % | 뺌 |

바렌츠해의 제4기 이전 지질은 BGR 의 유럽 500만 지질도(Asch 2005)이고 육지까지 칠한다 — 스발바르 땅 위에서는 NPI 지질도가 더
자세하다. 레이어 차례는 사람이 정한다.

**속성.** `application/json` 이 돈다. 열을 `FRIENDLY` 에 적은 것만, 적은 차례로 보인다 — 암상·지질시대·원 범례·축척·참고 문헌,
퇴적물은 Folk 7·16 갈래와 원 분류·자료·보유 기관, 단층은 종류·이름. 지질시대(`label_age`)만 ICS 한글판으로 옮긴다(값의 나머지는
옮기지 않는 규칙).

## 4. 버린 것

- **EMODnet 을 3035(유럽 람베르트 등적)로 받기** — 스발바르에서 왜곡이 작아 3857 보다는 낫지만, 3413 이 되는 것을 안 뒤로는 까닭이 없다
- **얀마옌 탭에도 `@janmayen` 별칭으로 걸기** — 이름이 둘이 되면 캐시도 둘로 갈린다. 빌리기로 풀 수 있지만 위의 까닭으로 하지 않았다
- **GEBCO 의 누른 자리 수심** — 배경은 누르지 않는다. 수심은 이미 표고 읽기(070)가 준다
