# 관리 화면 — 개인 레이어 반입, 저장 자료 관리, 첫 자료 nkfcluster

2026-10-01 · `feature/personal-layers` · wetherilli

계획은 P08. 여기는 만들며 고른 것과 첫 자료를 옮긴 일이다.

## 읽개 하나를 셋이 쓴다

`personal.js` 가 양식을 읽고(`parse`) 다시 쓰고(`toGeoJSON`·`toCSV`) 저장소에 넣고 뺀다. 관리 화면과 지도가 같은 파일을
싣고, 시험은 node 로 같은 파일을 부른다(`tests/js/personal_check.js`). 양식을 읽는 법이 셋으로 갈라지면 "관리 화면에서는
받았는데 지도에는 다르게 뜬다" 가 생긴다.

- **잃지 않는 쪽으로 읽는다.** 형식이 `number` 인 칸에 숫자가 아닌 글자가 오면 글자 그대로 둔다. 앞뒤 공백도 그대로다.
  좌표를 못 읽은 행은 버리지 않고 `geometry: null` 로 들고 다닌다 — 지도에만 안 뜬다
- **CSV 는 EUC-KR 도 읽는다** — 한국어 엑셀의 "CSV 로 저장" 이 그렇다. UTF-8 로 엄격히 풀어 보고 안 되면 EUC-KR
- 좌표 칸의 별명(`경도`·`위도`·`x`·`y`)은 읽되 경고한다. 기존 점묶음 업로드가 별명을 받아 와서, 그 파일을 그대로 넣는
  사람이 있을 것이다. 양식은 `lon`·`lat` 하나다

## 관리 화면

`/GSM/manage/`. 색·단추·상자는 `map.css` 를 빌리고 테마·글꼴은 지도에서 고른 것(`gsm.theme` 등)을 따른다. 탭 둘.

- **개인 레이어 반입** — 끌어 놓으면 저장하기 전에 읽은 것을 보인다: 점/면, 행 수, 지도에 뜨는 수, 좌표 없는 수, 열과 형식,
  앞의 몇 행, 읽지 못한 줄과 까닭. 이름·색·이름표 열은 여기서 고친다. 양식 예시(점·면 × JSON·CSV)를 내려받을 수 있다
- **저장 자료 관리** — 개인 레이어마다 보이기·색·이름 고치기·JSON/CSV 내려받기·지우기. 쓰는 저장소의 양과
  `navigator.storage.persist` 청하기(브라우저가 공간이 모자랄 때 지우지 않게). 그리고 **이 브라우저의 설정** —
  localStorage 의 `gsm.*` 를 뜻(지역 탭·켠 레이어·보던 자리…)과 함께 보이고 하나씩 또는 통째로 지운다. 지도가
  이상해졌을 때 "저장소를 지워 보라" 를 말로 설명하지 않아도 된다

관리 화면은 계정을 묻지 않는다. 지우고 고치는 것이 그 브라우저의 것뿐이다. 서버를 고치는 기능이 오면 그때 막는다.

## 지도

- 바닥의 **관리** 단추 — 설정의 왼쪽
- **개인 레이어 블록** — "그리기" 위에 따로 둔다. 사람이 "음영도를 건드려 다르게 보이게" 하라고 했다. 블록은 한 단 깊은
  바탕에 안쪽 그림자·점선 테, 머리는 빗금이다. 지도 위 기호도 점묶음(흰 테 동그라미)과 갈라 **어두운 테의 네모에 그림자**,
  면은 끊긴 테다. 겹침 거르기(declutter)를 기호에 걸면 한 점의 그림자와 네모가 서로를 지워 그림자만 남았다 —
  `declutterMode: "none"` 으로 이름표에만 건다
- 팝업 — 양식의 `label` 로 열 이름을 적는다. 한 자리에 레이어마다 8 건까지, 넘치면 "n건 더" 한 줄. nkfcluster 는 지역
  대표점이라 초산-고풍 한 점에 184 건이 겹친다
- 관리 화면에서 바꾸면 열린 지도가 따라온다(BroadcastChannel). 투영이 바뀌면 위경도에서 다시 옮긴다

## 첫 자료 — nkfcluster 전체목록

`http://paleolab/nkfcluster/occ_list/` 는 같은 서버의 phyloserver 다(`paleolab` 은 이 기계). 1 072 건.
**자료는 저장소에 두지 않는다** — 연구실 내부 자료다. 만든 것과 스크립트는 `~/GSM-personal/nkfcluster_occ/` 에 있다.

**긁은 길.** 목록은 20 건씩 54 쪽에 보이는 이름만 준다. 내려받기(xlsx)는 코드까지 주지만 id 가 없다. 그래서
xlsx(id 순) + 목록 54 쪽(id) + 출처 갈래 거르기 다섯 번(source_code) + 상세 1 072 쪽을 받아, xlsx 의 i 번째를 i 번째로
작은 id 에 붙이고 **상세 쪽과 한 칸씩 맞춰 보았다 — 어긋남 0.** 출처 갈래 다섯의 합(431+172+245+118+106)도 1 072 다.
DB 를 바로 읽지 않은 것은 운영 MySQL 의 비밀번호를 꺼내야 해서다. 웹은 읽기만 한다.

**좌표가 없다.** occ_list 의 산지는 "황주"·"승호-사동" 같은 지역 이름(코드 32 개)뿐이다. 사람이 고른 길 —
같은 DB 의 occ2(조선의화석 삼엽충 495)·occ6(완족류/산호 331)은 마을 단위 위경도와 같은 지역 코드(`location_code`)를
갖는다. 그 코드마다 **서로 다른 위경도의 평균**을 대표점으로 삼았다(같은 산지의 표본 수로 무게를 주지 않았다 — 표본이
많은 마을 하나로 끌려간다). 15 개 지역이 이렇게 채워진다. occ2·occ6 에 없는 12 개 지역(혜산·평산-금천·연탄·중강·장진·
강서-강동·은산·구장·맹산·옹진-강령·연산-신평·남포, 222 건)은 **OSM 행정구역의 대표점**(Nominatim 한 번, 16 회)으로,
두 군을 이은 이름은 둘의 평균으로 채웠다. 산지가 빈 7 건만 좌표가 없다.

대표점이지 산출 지점이 아니라는 것을 자료에 적었다 — `coord_source`(낸 법)·`coord_n`(평균에 든 곳 수)·
`coord_spread_km`(가장 먼 곳까지, 강서-강동 29.5 km 가 가장 넓다). 좌표표는 `location_coords.csv` 로 따로 두어 사람이
고칠 수 있다.

## 소실 검사

`verify.js` 가 **브라우저가 쓰는 읽개 그대로** JSON·CSV 를 읽어 본다.

| 본 것 | 결과 |
|---|---|
| 원본(xlsx 16 칸 + 상세 11 칸 + 출처 갈래) ↔ JSON | 30 016 칸, 어긋남 0 |
| 원본 ↔ CSV | 30 016 칸, 어긋남 0 |
| 공백까지 한 글자씩 (원본에 앞뒤 공백이 있는 칸 18) | 어긋남 0 |
| JSON ↔ CSV (속성·좌표·형식·열 설명·머리) | 같다 |
| 관리 화면의 내려받기로 되쓴 것을 다시 읽기 (JSON→JSON·CSV, CSV→JSON·CSV) | 같다 |

**옮기지 못한 것 하나** — 모델의 `index` 칸(입력 순번)은 목록·상세·xlsx 어디에도 나오지 않아 웹으로는 받을 수 없다.
id 는 `id` 로 그대로 갔다. 지질시대는 이름과 ChronoUnit 번호만 갔고 그 시대의 Ma 는 옮기지 않았다 — 산출 기록의 칸이
아니라 ChronoUnit 표의 칸이다.

되쓰기에서 하나 고쳤다 — CSV 머리의 `version` 이 글자 `"1"` 로 읽혀 JSON 의 `1` 과 달랐다. 판 번호만 숫자로 읽는다.
