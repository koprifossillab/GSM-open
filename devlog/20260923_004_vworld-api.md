# 004 — VWorld 로 더 할 수 있는 것

2026-09-23

배경지도를 붙이고 나니 "이 열쇠로 또 무엇을 할 수 있나" 가 남았다. 훑어보고
**쏴 보고** 갈랐다. 아래의 "된다·안 된다" 는 전부 실제 호출로 확인한 것이고,
확인 못 한 것은 그렇게 적었다.

호출은 `Referer: http://paleolab/GSM/` 와 브라우저 User-Agent 를 붙여 했다.

## 제일 큰 것 — WMS 187 종

문서에 목록이 없어서 `GetCapabilities` 로 직접 뽑았다.

```
http://api.vworld.kr/req/wms?SERVICE=WMS&REQUEST=GetCapabilities&VERSION=1.3.0
  &KEY=<키>&DOMAIN=http://paleolab/GSM/
```

200, 143 KB, **레이어 187 종.** `GetMap`·`GetFeatureInfo` 둘 다 돌고, 지원
좌표계에 **EPSG:3857 이 있어** 우리 화면에 그대로 얹힌다.

**우리 얼개에 그냥 들어온다.** `TileWMS` 하나 더 만들어 레이어 패널에 세우면
끝이다 — 켜기·순서·투명도·속성 읽기가 이미 있다. 지도 엔진을 건드릴 일이 없다.

지질에 곧바로 쓸모 있는 것 (그려지는 것을 확인했다):

| 레이어 | 뜻 |
|---|---|
| `lt_l_gimsfault` | 단층 — 속성도 뜬다 |
| `lt_l_gimslinea` | 지질구조선 |
| `lt_c_gimshydro` | 수문지질단위 |
| `lt_c_uj401` | 온천지구 |
| `lt_l_frstclimb` | 등산로 — **노두 접근로다** |
| `lt_p_nsnmssitenm` | 국가지명 (축척 제한이 있다) |
| `lt_c_wkmstrm` | 하천망 |
| `lt_c_adsigg`·`ademd`·`adri` | 시군구·읍면동·리 |

**WFS 로 같은 것을 벡터로도 준다** (`OUTPUT=application/json` → GeoJSON).
단층을 벡터로 받으면 선 색·굵기를 우리가 정할 수 있어 그림보다 낫다.

## 점 하나로 묻는 길 — 시료 지점에 쓸모가 크다

데이터 API 가 `geomFilter=POINT(경도 위도)` + `buffer=미터` 를 받는다.
확인한 것들:

- 시료 좌표의 **읍면동** — `data=LT_C_ADEMD_INFO`
- 시료에서 **가장 가까운 단층** — `data=LT_L_GIMSFAULT&buffer=20000` → 4 건
- 둘레 **국가지명** — `data=LT_P_NSNMSSITENM&buffer=1000` → `밑마루`·`정삼골`
  같은 토박이 지명이 온다

주소 API 도 양방향으로 돈다 — 주소→좌표, 좌표→지번·도로명·우편번호.

**함정**: 데이터 API 의 자료 이름이 WMS 레이어명과 다르다. `LT_C_ADEMD` 는
`INVALID_RANGE` 로 멈추고 `LT_C_ADEMD_INFO` 라야 돈다.

## 배경지도가 다섯이었다

WMTS 목록을 뽑으니 `Base`·`Satellite`·`Hybrid`·**`midnight`**·**`white`** 다섯이다.
`gray` 는 없다(문서에 있는 줄 알았는데 `InvalidParameter`).

**`white`(백지도)가 지질도 밑에는 `Base` 보다 낫다** — 도로·지명 색이 죽어
있어 분홍·자홍과 안 다툰다.

덤: 테마 위성영상에 `AntarcticaSejong`·`AntarcticaJangbogo`(세종·장보고기지)가
있다. 다만 **테마는 자리 차례가 `z/x/y` 로 배경지도(`z/y/x`)와 반대다.**
실제로 도는지는 확인 못 했다.

## 3D — 별도 화면이어야 한다. 권하지 않는다

이건 분명히 적는다.

**확인한 것**

- VWorld 3D 엔진(`WSViewerStartup.js`, 5.2 MB)은 **Cesium 을 포크한 것이다** —
  `terrainProvider`·`sampleTerrain`·`3d-tiles`·`Cartesian3` 가 들어 있다
- **우리 키는 3D 쪽에서도 유효하다** (`vworldIsValid = 'true'`)
- **결정적인 것**: `vw.ol3WebGL.v30.js` 가 **자기 OpenLayers 7.5.2 를
  `document.write` 로 따로 심는다.** 우리 OL 9.2.4 와 한 페이지에 두 벌이 뜬다.
  그리고 2D(OL)와 3D(Cesium 포크)는 서로 다른 지도 인스턴스다 — 3D 는 OL 위에
  덮는 겹이 아니라 **옆에 세우는 딴 지도다**
- 엔진 안에 `ws3d.common.map.WmsLayerElement` 와 `vw.source.TileWMS` 가 있어
  **바깥 WMS 를 3D 지형에 걸치는 자리는 마련돼 있다.** 다만 우리 KIGAM WMS 가
  실제로 걸쳐지는지는 **확인 못 했다** — 이 장비에 브라우저가 없다

**표고(DEM)를 점 단위로 얻는 길은 막혀 있다**

- 엔진이 쓰는 주소는 하나뿐이다:
  `xdworld.vworld.kr:8080/XDServer/requestLayerNode?Layer=dem&...`
- **쏴 봤다. 전부 막혀 있다.** 우리 키로도, 엔진에 박혀 있던 키로도,
  레벨 0·1·8 다, https 도 — 예외 없이 `<Error code="ERROR_DB_GENERAL">`.
  **두 키가 똑같이 실패하므로 우리 키 탓이 아니라 그 창구가 닫힌 것이다**
- 브라우저 안에서는 `createLineStringZWithSampleTerrain` 으로 지형에서 Z 를
  뽑을 수 있으나 **3D 화면이 떠 있어야만** 쓸 수 있다. 서버가 시료 목록을
  훑어 고도를 채우는 데는 못 쓴다

**대가**: 딴 화면 하나, OL 두 벌 갈라내기, 5 MB 엔진. 그런데 3D 의 가장 큰
쓸모였을 "시료 고도 붙이기" 가 막혀 있다. 하려면 먼저 브라우저가 있는 데서
작은 실험 페이지로 "VWorld 3D 지형 위에 KIGAM WMS 가 걸쳐지나" 만 재 보고
판단하는 것이 옳다.

## 브라우저에서 부를 때 — CORS

| 창구 | `Access-Control-Allow-Origin` | 뜻 |
|---|---|---|
| WMTS 타일 | `*` | 브라우저가 곧장 부른다. 지금 그렇게 쓴다 |
| WMS `GetMap` | 없다 | `<img>` 로 받는 `TileWMS` 는 **돈다** |
| WMS `GetFeatureInfo` | 없다 | `fetch` 로는 막힌다 → **중계해야 한다** |
| WFS GeoJSON | 없다, JSONP 도 안 된다 | **중계가 필수다** |
| 데이터·검색·주소 API | 없다, **JSONP 는 된다** | 곧장도 되고 중계도 된다 |

`GetFeatureInfo` 를 쓰려면 어차피 중계가 필요하니, **WMS 는 처음부터 중계로
가는 편이 낫다.** 그러면 열쇠도 안 나가고 타일 캐시(`tilecache.py`)도 그대로 탄다.

덤: **도메인 제한이 WMTS 에서는 안 걸린다.** `Referer` 를 빼도, 엉뚱한 것을
줘도 타일이 온다. JS API 쪽 검사에서만 도메인을 본다.

## 여기에도 상류의 함정이 있다

`GetCapabilities` 에 이름이 있어도 그려진다는 보장이 없다. 쏴 보고 빈 것들:

- 연속지적도(`lp_pa_cbnd_bubun`) — WMS 는 **빈 타일**, 그런데 **WFS 로는 온다**
- 도로명주소건물(`lt_c_spbd`)·도로(`lt_l_sprd`) — 빈 타일
- 토양도(`lt_c_gimsscs`) — **WMS·WFS 둘 다 비었다.** 자료 자체가 없다

**001 과 같은 일이다.** 얹기 전에 한 장씩 쏴 보고 `verified_at` 을 남겨야 한다.
카탈로그를 표로 두는 까닭이 여기서 또 확인됐다.
