# 시료 고도 붙이기 — 표고 타일에서 점마다 고도를 읽는다 (계획)

2026-09-27 · sclee · 004(VWorld DEM 창구가 닫혔다)·015(3D 가 표고 타일을 읽는다) 다음.
**지었다 (2026-09-29, devlog 031).** 극지는 계획의 (나) 대신 PGC 의 `identify` 로 갔다 —
031 이 까닭을 적었다. 아래는 계획으로 남겨 둔다.

시료 목록에 고도 열이 없거나 GPS 고도라 믿기 어려운 일이 흔하다. 004 는
VWorld 3D 의 표고 창구(`XDServer … Layer=dem`)가 닫혀 이 일을 접었다. 015 에서
3D 를 MapLibre + 공개 표고 타일로 지으면서 **표고를 우리가 직접 읽을 수 있게
됐다** — 서버가 점묶음을 훑어 점마다 고도를 채울 수 있다.

## 1. 표고를 어디서 읽나

| 원천 | 덮는 곳 | 해상도 | 형식 | 높이의 기준 |
|---|---|---|---|---|
| **AWS Terrain Tiles** (Terrarium) | 전 지구. SRTM 은 60°N–56°S | SRTM 약 30 m (015) | PNG 타일, `z/x/y` | SRTM 은 EGM96 지오이드 |
| **ArcticDEM** mosaic v4.1 (PGC) | 60°N 위 — 그린란드·스발바르 | 2 · 10 · 32 m | COG(GeoTIFF), EPSG:3413 | WGS84 타원체 |
| **REMA** mosaic v2.0 (PGC) | 남극 | 2 · 10 · 32 m | COG(GeoTIFF), EPSG:3031 | WGS84 타원체 |
| VWorld DEM | — | — | **닫혔다** (004, 2026-09-27 에도) | — |

- Terrarium 은 3D 가 이미 부르는 것이다:
  `https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`
  (`map3d.js`, `maxzoom 15`, 256 px). 열쇠가 없다. 값은
  `(R × 256 + G + B / 256) − 32768` 미터
- SRTM 밖에서 Terrarium 이 무엇을 섞는지(ETOPO1·GMTED 같은 거친 판인지,
  ArcticDEM 을 섞었는지) **확인하지 않았다.** 값은 나오겠지만 해상도를 모르면
  출처로 적을 수가 없다 — 그래서 극지는 원자료로 간다
- ArcticDEM·REMA 는 공개 S3 `pgc-opendata-dems`(us-west-2, 열쇠 없음,
  CC BY 4.0) 에 COG 로 있다. 예: `rema/mosaics/v2.0/32m/<타일>/<타일>_32m_v2.0_dem.tif`,
  `arcticdem/mosaics/v4.1/…` 도 같은 짜임. 타일 번호는 극평사 격자이고
  STAC·타일 색인이 함께 있다
- **높이의 기준이 다르다.** SRTM 은 지오이드(해발에 가깝다), ArcticDEM·REMA 는
  타원체고다. 그린란드·남극에서 둘의 차(지오이드고)는 수십 m 다 — 모르고
  섞으면 시료 고도가 그만큼 틀린다. §3 에서 값마다 기준을 적는다

## 2. 무엇으로 읽나 — web 이미지에는 GDAL 도 numpy 도 없다

`requirements-web.txt` 는 **일부러** Django·Pillow·requests·whitenoise·gunicorn
뿐이다("이 경계가 web 이미지를 200 MB 대로 유지한다"). 그 경계 안에서:

**Terrarium PNG — 쉽다.** Pillow 가 이미 있다. 점의 위경도 → 타일 번호·픽셀
자리(웹 메르카토르 셈, `tilegrid` 쪽에 이미 비슷한 것이 있다) → PNG 한 장 →
네 픽셀 쌍선형 보간. 파이썬 몇십 줄, 새 의존이 없다.

- **z12 를 쓴다.** 37°N 에서 한 픽셀이 약 30 m — SRTM 해상도와 맞는다. 그 위
  확대는 늘려 그린 것일 뿐 새 정보가 없고 타일 수만 늘린다
- 점을 타일별로 묶어 **한 타일은 한 번만** 받는다. 한 지역의 시료 수백은
  타일 몇십 장이다

**COG — 어렵다.** 할 수는 있다: HTTP Range 로 머리의 IFD 를 읽고, 점이 든
내부 타일(보통 512×512) 하나만 받아 풀면 된다. 그러나 GDAL 없이 하려면
TIFF 머리 해석(`struct`) · 압축 풀기(DEFLATE 는 `zlib`, LZW 는 손으로) ·
부동소수 예측자(predictor 3) 되돌리기 · 극평사 좌표 셈(3413·3031 — `crs.py` 에
TM 은 있으나 극평사는 없다)을 다 우리가 쓴다. numpy 없이 262 144 개 값을
되돌리는 것도 느리다. 압축·예측자가 실제로 무엇인지는 **한 장 받아 보고
정한다**(확인하지 않았다).

그래서 세 길을 견준다:

| 길 | 좋은 것 | 대가 |
|---|---|---|
| (가) web 이미지 안에 작은 COG 읽개 | 화면 단추 하나로 극지도 된다 | 손으로 쓴 TIFF·LZW·극평사 셈. 틀리기 쉽고 시험이 많이 든다 |
| (나) **web 이미지 밖의 명령** | GDAL(`/vsicurl/`)·rasterio 로 몇 줄. 검증된 길 | 사람이 서버에서 부른다. 화면 단추가 극지에서는 "명령을 부르라" 로 뜬다 |
| (다) 미리 뽑은 거친 격자 | 서버는 표 하나 읽기 | 1 km 격자면 산악 시료에는 쓸모가 없다 |

**권하는 것: 한국(Terrarium)은 web 안에서, 극지는 (나).** 극지 점묶음은 수가
적고 한 번 채우면 끝이다. TODOs 의 "남극: 우리가 그리는 길" 도 GeoPackage 를
읽으려면 같은 web 밖 도구가 필요하다 — 두 일이 한 도구 자리(`tools/`,
호스트의 `~/venv/GSM` 에 GDAL)를 나눠 쓸 수 있다. (가) 는 극지 시료가 잦아지면
다시 본다.

## 3. 어디에 두나

**`Point` 에 칸을 셋 더한다.** 딸린 속성(`props`)에 넣지 않는다.

```python
elev = FloatField("표고 (m)", null=True, blank=True)       # 우리가 읽은 값. 1 m 에서 자른다
elev_source = CharField("표고 출처", max_length=40, blank=True)
    # "terrarium-z12" · "arcticdem-32m-v4.1" · "rema-32m-v2.0"
elev_datum = CharField("높이 기준", max_length=12, blank=True)   # "egm96" · "wgs84-ellipsoid"
```

- `props` 에 넣지 않는 까닭 — `props` 는 **올린 사람의 원본 열**이다. 원본에
  `고도`·`elevation` 열이 이미 있을 수 있고, 그것은 실측(GPS·고도계)이다.
  우리 값이 그 옆에 섞이면 어느 것이 잰 것이고 어느 것이 DEM 에서 읽은 것인지
  가를 수 없다. **원본 열은 절대 덮지 않는다**
- 출처·기준을 값마다 적는 까닭 — 같은 점묶음 안에서도 60°N 을 넘나들면 원천이
  갈린다. 나중에 "이 고도는 어디서 왔나" 를 답할 수 있어야 한다(CLAUDE.md
  "받아온 것의 순위" 의 같은 뜻)
- 모양(`Shape`)은 채우지 않는다. 선의 고도 단면은 다른 일이다
- 채운 때를 따로 두지 않는다 — 다시 채우면 덮는다. 원천이 판을 올리면
  (`v4.1` → 다음) 출처 칸이 달라져 알아볼 수 있다

**화면·내려받기**: GeoJSON 의 `properties` 에 `표고(DEM)`·`표고 출처` 두 칸으로
싣는다 — 팝업에 뜨고 QGIS 로도 간다. 이름을 "고도" 로 하지 않는 까닭은 원본
열과 부딪히지 않게 하려는 것이다. `PROP_EN` 에 영어를 적는다.
**함께 고칠 것**: 지운 점묶음의 사본도 `_pointset_features` 를 쓴다. 되살리기
(`pointsets.restore`)가 지금은 `이름표` 만 떼므로, 이 두 칸도 떼어 제 칸으로
돌려야 한다 — 안 그러면 되살린 점의 `props` 에 섞여 들어간다.

## 4. 화면 — 점묶음 줄의 단추 하나

2D 점묶음 줄에 **"고도 채우기"** 단추(아이콘 단추, 제목 글로 뜻을 밝힌다).

- 누르면 `POST /GSM/pointsets/<id>/elevation/` → 서버가 채우고 "412 점 채움 ·
  3 점은 원천 밖" 처럼 돌려준다. 원천 밖(바다 위 −값, 극지인데 (나)를 안
  돌렸다)은 비워 두고 센다
- 한 번에 **점 2 000 까지** 요청 안에서 한다. 넘으면 "명령으로 채운다" 안내와
  함께 `manage.py fill_elevation <번호>` 를 적어 준다
- 극지 점은 화면에서 채우지 않는다(§2). 명령은 같은 이름으로 `--polar` 를 받는다
- 실험 기능 안에 둘지는 §7

## 5. 예의 · 캐시 · 문

- **새 상류는 새 문이다** — `viewer/elevation.py`. CLAUDE.md 의 "상류마다 문이
  하나" 그대로, 여기 말고는 `requests` 를 부르지 않는다. 구조 목록에 한 줄 더한다
- `User-Agent: GSM/0.1`. 타일은 **한 번에 한 장**, 사이를 둔다(prewarm 과 같은
  마음 — 한도를 재지 않는다, 010). `UpstreamDay` 에 `aws` 로 센다
- 받은 PNG 는 `tilecache` 에 `terrarium/12/x/y` 로 담는다 — 007 대로 계속
  보태고 스스로 지우지 않는다. 3D 가 브라우저에서 받는 것과는 따로다(브라우저는
  AWS 에서 곧장 받는다)
- 디스크 여유 5 GB 밑이면 담지 않고 읽기만 한다(007 의 규칙)
- PGC 는 "대량으로 받을 때는 연락하라" 고 적는다 — 우리는 점이 든 내부 타일만
  읽으니 해당되지 않지만, (나)가 도는 날 한 번 확인한다
- 출처 표기: 팝업·내려받기에 `표고 출처` 가 이미 실린다. ArcticDEM·REMA 는
  CC BY 4.0 이라 **인용 문구**(PGC 가 정한 것)를 설정의 "출처" 칸에 둔다

## 6. 순서

1. `elevation.py` — Terrarium 한 장 받기·풀기·보간. 망 없이 시험한다(합성 PNG)
2. `Point` 에 세 칸 + 이주. GeoJSON 에 두 칸, 되살리기 고침
3. `manage.py fill_elevation <번호>` — 한국부터
4. 2D 단추와 `POST …/elevation/`
5. 극지 — (나)의 도구. GDAL 이 있는 곳에서 돈다. 이것만 따로 낸다

1~4 가 한 판, 5 는 극지 표고(TODOs)·남극 굽기와 함께 본다.

## 7. 확인하는 법

- **단위 시험**: Terrarium 풀기 식(알려진 RGB → 알려진 m), 위경도 → 타일·픽셀
  (경계·반올림), 보간(네 모서리 값이 다를 때), 원본 `고도` 열이 안 덮이는지,
  되살리기가 두 칸을 제 자리로 돌리는지
- **알려진 높이와 견준다.** 봉우리는 나쁜 시험이다 — DEM 은 꼭대기를 깎아
  낮게 읽는다(30 m 칸의 평균). 그래도 한 번은 본다: 설악산 대청봉 1 708 m,
  지리산 천왕봉 1 915 m, 한라산 1 947 m — **수십 m 낮게** 나오면 정상이다
- 더 나은 것은 **평지·완만한 곳의 삼각점**이다. 국토지리정보원이 표고를 밝힌
  삼각점 스물 남짓을 골라 ±15 m 안에 드는지 본다(SRTM 의 알려진 오차 수준)
- 극지: 세종기지·장보고기지(해안, 수십 m 안), 그린란드 Summit Station(약
  3 200 m). **타원체고와 해발을 헷갈리지 않았는지**가 여기서 드러난다
- 같은 점을 3D 에서 클릭해 본 자리의 지형과 어긋나지 않는지(P02 뒤)

## 8. 사람에게 묻는 것

1. **극지를 (나)로 가도 되나** — 서버에서 사람이 명령을 부르는 길. 아니면 (가)
   작은 COG 읽개를 web 안에 쓰는 품을 들일 만큼 극지 시료가 잦은가
2. **높이 기준을 맞출까** — 극지 값을 타원체고 그대로 두고 기준만 적을지,
   EGM2008 지오이드고 격자(작은 표, 1° 격자면 수백 KB)로 빼서 해발로 맞출지.
   맞추면 한국 값(EGM96)과 견줄 수 있다
3. **원본에 고도 열이 있을 때** — 그래도 채우는가(둘을 나란히 보이면 GPS 고도가
   틀린 점이 드러난다), 아니면 건너뛰는가
4. **단추를 실험 기능 안에 둘까** — 3D 와 상관없이 쓸모 있는 일이라 밖에 둬도
   되지만, 값이 한 번 들어가면 내려받기에 실려 나간다
5. 해상도 — 극지는 32 m 로 충분한가, 10 m 를 볼 것인가(한 점에 받는 양은 같다.
   타일 수만 는다)
