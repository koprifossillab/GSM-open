# 공개용 저장소 GSM-open — 소스 링크를 개발 저장소에서 떼어 둔다

2026-10-02 · `feature/open-repo` · wetherilli

## 1. 무엇을 바랐나

사용자: 라슈 컴퍼니(`wetherilli/rash-company` 비공개 + `rash-company-open` 공개 + Pages)처럼 **공개용 저장소를 따로 두고 기존 소스는
비공개로** 돌리고 싶다. 다만 비공개 전환은 천천히 하고, **지금은 소개 화면의 소스 링크만 공개용으로** 바꾼다.

## 2. 무엇을 했나

- 공개용 저장소는 `koprifossillab/GSM-open`(사용자가 고름 — WegenersDream 처럼 연구실 계정)
- 소개 화면 맨 아래의 "소스" 링크가 `settings.SOURCE_URL`(기본 GSM-open, `GSM_SOURCE_URL` 로 바꿀 수 있다)을 가리킨다
- `deploy/publish_open.sh <태그>` — 그 태그의 파일을 GSM-open 에 **한 커밋으로 통째로 덮고 같은 태그를 단다**. 판 세션이 릴리스 뒤에
  부른다(CLAUDE.md "커밋과 PR"). `.claude/` 만 뺀다

## 3. 왜 이렇게

- **소스 링크는 AGPL 13조의 길이다.** 링크를 GSM-open 으로 돌리면 GSM-open 에 지금 도는 판의 소스가 있어야 한다. 그래서 링크만
  바꾸지 않고 판마다 사본을 미는 절차를 같이 깐다. 개발 저장소를 나중에 닫아도 링크를 다시 손댈 일이 없다
- **역사는 옮기지 않는다.** 개발 저장소의 커밋에는 세션끼리의 메모·고쳐 쓴 흔적이 많다. GSM-open 은 "판 하나 = 커밋 하나" 로 둔다 —
  밖에서 받는 사람에게는 그 판의 소스면 된다. 운영 이미지(`koprifossillab/gsm:<태그>`)가 같은 태그에서 구워지므로 받는 소스와 도는
  코드가 같다
- 빼는 것을 `.claude/` 하나로 둔 까닭 — 지금 개발 저장소가 공개라 나머지는 이미 밖에 있다. 비공개로 돌릴 때 무엇을 더 뺄지
  (예: 세션 메모, 내부 검토 문서) 다시 정한다

## 4. 비공개로 돌릴 때 걸리는 것 (미룸)

사용자가 "천천히" 라고 했다. 그때 볼 것을 적어 둔다.

- 바꾸는 것은 저장소 주인(`koprifossillab` 계정)이다. 다른 계정(wetherilli·jikhanjung …)은 협업자로 넣어야 계속 일한다
- **CI 분량** — 공개 저장소의 Actions 는 무제한이지만 비공개 개인 계정은 한 달 2 000 분이다. 2026-10-02 하루에 PR 이 스무 남짓이었고
  PR 마다 세 job 이 5 분 남짓이다. 넘치면 CI 가 멈춰 "CI 통과해야 병합" 이 막힌다 — 이 서버에 자체 러너를 두는 것이 대책이다
- **Docker Hub 이미지 `koprifossillab/gsm` 이 공개다** — 소스와 씨앗이 들어 있다. 저장소만 닫으면 이미지로 샌다. 같이 닫거나
  (무료는 비공개 하나) 공개 이미지에는 GSM-open 과 같은 것만 넣는다
- GitHub Pages 는 비공개 저장소에서 유료라, 연구소 밖 경로를 Pages 로 낸다면 GSM-open 쪽에 둔다

## 5. 연구소 밖 경로는 따로

사용자는 연구소 밖에서 **한국 지질도와 극지 지질도**를 보고 싶어 한다. 둘 다 서버가 있어야 한다 — 한국은 KIGAM 인증키를 서버가 숨겨
붙이고, 극지는 NPI·GEUS 를 서버가 대신 받는다. 그래서 GitHub Pages 의 고정 사본(WegenersDream tupandactyl 029 의 길)으로는 안 되고,
서버에 밖에서 닿는 길(공인 주소나 터널 — 둘 다 연구소 승인)과 서버가 검사하는 PIN 문이 필요하다. Pages 에 PIN 화면을 두면
문패일 뿐 자물쇠가 아니다(파일이 공개 주소에 그대로 있다). 검토는 따로 쓴다.
