# 3D 에 유럽·일본 지질도, 온 지구 찾기에 화석 산지·지층·화산

2026-10-04 · `feature/3d-europe-earth-search` · wetherilli

판 세션이 `docs/새_일거리.md` 의 §8 과 §5 를 한 갈래로 맡겼다. 둘은 서로 상관이 없다. 고칠 파일이 겹치지 않아 한 PR 에 담았다.

## 1. 3D 에 유럽 탭과 일본 지질도 (§8)

3D 는 `wms/` 의 3857 타일만 얹는다. 그래서 `views.map3d_view` 에 상류의 허용 목록을 둔다. 유럽의 새 상류(BGS·GSNI·BRGM·EGDI·
BGR·IGME·GSI·EMODnet)는 2D 에서 이미 `wms/` 를 타는데 목록에만 빠져 있었다. 목록을 `MAP3D_WMS` 로 빼고 이들을 더했다. 3D 의
지역 묶음(`BUNDLES`)에도 유럽(영국·아일랜드·프랑스·독일·스페인)을 더했다.

### IGME 1:100만 — 4326 인데 넣었다

2D 는 IGME 1:100만을 4326 으로 받는다. `igme.py` 의 머리말에 "3857 을 그려 주지 않는다" 고 적혀 있어 빼야 하나 했다. 그래서 2026-10-04 에
문(`igme.get_map`)으로 마드리드 둘레 3857 타일을 한 장 물었다. 200 으로 제대로 된 지질도가 왔다. 문은 1.3.0 을 1.1.1 로 옮겨 `SRS=EPSG:3857` 로
묻는데, 그 꼴은 받는 것으로 보인다. 147 에서 3857 이 안 된 것이 1.3.0 의 `CRS` 였는지는 따지지 않았다. 2D 는 그대로 4326 으로 둔다 —
2D 를 바꾸면 쌓인 캐시가 버려진다. 3D 만 3857 로 묻는다.

EMODnet 은 북극해 판(2D 3413)도 함께 들어간다. GeoServer 는 어느 투영이든 그리므로 3D 의 3857 물음에도 그림을 준다.

노르웨이 NGU(3575)·핀란드 GTK(3413)는 넣지 않았다 — 이번 범위가 아니었고, 3857 로 그리는지 재 보지 않았다.

### 일본 — z/x/y 를 그대로

GSJ 지질도와 지리원 주제 타일은 3857 z/x/y 다. 카탈로그 행에 이미 `tiles`(GSJ 는 우리 중계 `gsj/…`, 지리원은 지리원 주소)가 있다.
그래서 템플릿이 그 주소를 `data-tiles` 로 싣고, `map3d.js` 가 256 px raster 원천으로 받는다. 줌은 타일의 줌이라 2D 의 `minZoom`·`maxZoom` 을
원천에 그대로 건다.

### 줌과 범위도 2D 처럼

WMS 레이어 가운데 가까이서만(BGS 1:5만, 화면 줌 13 부터) 또는 멀리서만(BRGM 스캔) 그리는 것은 2D 처럼 그 밖에서 숨긴다. 2D 의 줌은
256 px 기준이라 MapLibre(512 px)보다 하나 크고, 2D 는 반 단계 넉넉히 보인다. 그래서 레이어의 `minzoom` 은 `min - 1.5`, `maxzoom` 은
`last - 0.5` 다. 범위(`bbox`)가 있는 레이어는 0.5° 넉넉히 원천의 `bounds` 를 건다. 유럽 묶음에서 스페인 판이 영국 바다를 묻지 않게 —
2D 의 묶음 탭과 같은 까닭이다(024).

### 확인

머리 없는 브라우저(SwiftShader)로 유럽 탭의 BGS(런던 줌 15)·IGME 1:100만(마드리드)·BGR GÜK250(카셀)과 일본 탭의 GSJ(후지산)를 열었다.
목록에 유럽 다섯 나라·일본이 섰다. 상류 요청 208 번이 모두 200 이었고, 페이지 오류는 없었다.

## 2. 온 지구의 찾기 칸에 화석 산지·지층·화산 (§5)

`earth/places/` 가 Natural Earth 지명에 더해 PBDB 의 산지 이름(`name`)·지층(`formation`)과 GVP 화산 이름을 함께 찾는다. 모두 모아 둔
파일(`pbdb.sqlite`·`gvp_volcanoes.json`)이라 상류를 타지 않는다.

- **지층은 이름으로 묶는다.** 한 지층에 산지가 수백 곳이다(Hell Creek 591). 산지를 다 늘어놓으면 찾기 칸이 한 지층으로 찬다. 그래서
  한 줄로 묶어 "화석 산지 N 곳" 을 덧붙인다. 그 지층의 자리로는 화석이 가장 많은 산지를 골랐다. 가운데(평균)는 넓게 흩어진 지층에서 아무
  산지에도 없는 자리가 되기 쉽다
- **섞는 차례** — 같은 이름 → 앞이 같은 것 → 들어 있는 것. 같은 차례면 지명·화산·지층·화석 순이다. "Etna" 는 화산이, "Hell Creek" 은 지층이
  맨 위에 선다
- **결과의 꼴** — 화면의 찾기 결과 꼴(`title`·`kind`·`lat`·`lon`)에 `group`(place·volcano·formation·fossil)과 덧말(`sub`: 지층·시대·나라·
  마지막 분화)을 더했다. 딱지(`kind`)는 지명이면 그 갈래(도시·강 …)이고, 나머지는 "화산"·"지층"·"화석" 이다. 출처 줄은 결과에 든 것만
  적는다(Natural Earth · GVP · PBDB)
- **다가가는 높이** — 화석 산지 30 km, 화산 60 km, 지층 400 km

### 색인을 굽지 않았다

27 만 줄을 `LIKE '%…%'` 로 훑어도 0.1–0.2 초다(운영 파일을 읽기로만 열어 쟀다). FTS5 색인을 더하려면 `pbdb.sqlite` 를 다시 구워야 한다.
운영의 파일을 다시 굽는 것은 사람의 일이다. 찾기 칸은 200 ms 를 쉬고 묻고, 한 번에 한 물음만 산다. 그래서 이 빠르기면 넉넉하다.
느려지면 그때 `fossils.build` 에 FTS5 표를 더한다. 두 글자보다 짧으면 찾지 않는다 — 한 글자는 거의 모든 줄에 맞는다.

시대 칸은 ICS 이름이면 한국어로 옮긴다(`i18n.age_ko`). 지역 층서 이름(Delamaran·Lancian 따위)은 ICS 표에 없어 그대로 둔다.
