# 연결 레이어 — API 의 목차 주소를 넣어도 자료 주소를 찾아간다

2026-10-01 · `fix/linked-endpoints` · wetherilli

0.31.0 에서 사람이 FSIS 를 이으니 "받지 못했다 — GeoJSON FeatureCollection 이 아니다" 가 떴다. 처음 받은 주소
`https://kofhin.psok.or.kr/fsis/api/v1/` 를 그대로 넣은 것이다 — 그 주소는 자료가 아니라 **API 의 목차**
(`{"endpoints": {"sites": {"url": …}, "site_detail": {"url_template": …}}}`)를 준다. 126 에서는 `…/sites/` 를 넣어 시험해
보지 못했다. 운영에서 목차 주소로 같은 오류를 다시 냈다.

## 목차면 거기 적힌 자료 주소로

받은 것이 양식으로 읽히지 않고 JSON 이면, `endpoints`(없으면 `links`, 없으면 문서 전체)를 세 단까지 훑어 `url` 을 모은다.

- **같은 호스트만** — 목차가 남의 호스트를 가리켜도 거기로 키를 싣지 않는다
- **자리표(`{id}`)가 든 것은 뺀다** — `site_detail` 의 `url_template` 같은 것. 그것은 하나짜리 상세다
- 셋까지 차례로 받아 보고 처음 읽히는 것을 쓴다. 다 안 되면 "API 의 목차다 — 자료 주소를 찾지 못했다 (주소들)"
- 찾으면 **연결의 주소를 그것으로 바꿔 적는다** — 관리 화면의 칸도 바뀌고, 다음부터는 곧장 자료 주소로 간다. 목차를 매번
  거치면 상대에게 두 번씩 간다

FSIS 목차에는 `sites` 하나뿐이라 망설일 것이 없다. 목차가 자료 주소를 여럿 적은 API 라면 처음 읽힌 것을 고르는데, 사람이
틀린 것을 받았다고 보면 칸을 고쳐 다시 받으면 된다.

하는 김에 **피처 하나(`"type": "Feature"`)도 받는다** — API 의 상세 주소(`…/sites/54/`)를 넣으면 산지 하나짜리 레이어가 된다.
