# Trek 판 목록 — 타일 한 장을 받아 보고 적는다

2026-09-30 · `feature/trek-probe-tile` · wetherilli

화성 세션이 넘긴 공통 틀 일이다(wetherilli 080). 씨앗 뽑기(`fetch_trek_catalog`)는 판의 `WMTSCapabilities.xml` 이
200 이면 타일 판(`kind: tile`)으로 적었다. 그런데 Capabilities 만 있고 **타일은 모두 404 인 판**이 있다 — 화성 사구 지대·
Hynek 골짜기망은 MapServer 만 둔다. 화성 세션이 손으로 `map` 으로 바꿔 두었지만 `kind` 는 사람의 칸이 아니라 다시
받으면 되돌아간다.

## 어느 타일을 받아 보나

판마다 한 장이면 된다 — 1 초 간격이라 한 판에 두 번 묻는 것도 달 1 200 판이면 40 분이다. 달·화성 판 열셋을 줌 0·2·끝에서
받아 보니 **있는 판은 줌 0 부터 다 200, 없는 판은 어느 줌에서나 404** 였다. 좁은 판(NAC 몇 km)도 줌 0 타일을 준다.
그래서 줌 0(두 장) 가운데 판 범위의 가운데를 덮는 한 장을 받는다.

가운데만 보면 틀리는 판이 있었다 — 화성 `CTX_Ortho_11S289E` 는 범위를 경도 −180…219° 로 적어 가운데가 동반구로
가지만 자료는 서경 71° 에 있다. 첫 장이 404 면 **나머지 한 장도** 본다. 404 인 판에만 한 번 더 묻는다.

## 화성 씨앗을 다시 받았다

`--reprobe` 로 243 판을 다시 물었다. 11 판이 바뀌었고 **모두 이미 숨긴 판이라 화면의 목록은 그대로다.**

- MapServer 판이 된 것 다섯 — SIM 3292(우리 지질도 레이어와 같아 숨김), 퍼서비어런스 경로, CRISM 광물 지표 둘
- 타일이 없는 판이 된 것 여섯 — CTX·HiRISE 전 지구, CTX 정사 넷(Capabilities 는 있는데 줌 0 두 장이 다 404)

다시 받을 때 칸의 차례가 처음 적을 때와 달라 씨앗 전체가 diff 에 잡혔다. 옮겨 적는 칸의 차례를 맞췄다 — 바뀐 판만 diff 에
선다.

달은 다시 받지 않았다(40 분). 다음에 씨앗을 새로 받을 때 함께 걸린다.
