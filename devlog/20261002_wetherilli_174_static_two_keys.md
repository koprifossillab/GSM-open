# 정적 판 — KIGAM·VWorld 키를 둘 다 각자, 처음 열 때 묻는다

2026-10-02 · `feature/static-keys` · wetherilli

사용자: "V월드도 사용자가 키를 받아서 입력하는 형태로 가자", "공개 지도를 켤 때부터 두 API 키를 사용자가 받아서 입력하도록 해."

## 1. 바꾼 것

- **VWorld 도 각자 키** — 정적 판의 `vworldKey` 는 페이지에 실린 값이 아니라 보는 사람이 넣은 키(`localStorage` 의 `gsm.key.vworld`,
  KIGAM 과 같은 30 일)다. `deploy/static_site.py` 는 이제 **어떤 키도 싣지 않는다** — 공개 판용 VWorld 키를 받아 싣던
  `--vworld-key-file`·`GSM_STATIC_VWORLD_KEY` 를 지웠고, VWorld 는 늘 상류에 든다
- **처음 열 때 묻는다** — 두 키 가운데 하나라도 없으면 창(`#key-dialog`)이 뜬다. 칸마다 무엇에 쓰이는지와 받는 곳 링크,
  VWorld 키를 받을 때 서비스 URL 에 적을 이 판의 주소, "이 PC 에 기억하지 않기"·"키 지우기"·"나중에"·"저장". "나중에" 는
  그 탭 동안만(`sessionStorage`) 다시 묻지 않는다. 저장하면 **다시 연다** — VWorld 배경·찾기는 화면이 시작할 때 키를 읽어 짓기 때문이다
- 한국 탭 위 알림 줄(`#static-key`)은 넣는 칸이 아니라 상태("둘을 넣었다"·"KIGAM 만 넣었다")와 "키 바꾸기" 단추가 됐다

## 2. 버린 것 — 공개 판용 VWorld 키 하나

검토 §10(wetherilli 164 의 실측)은 "배경은 누구나 봐야 하니 공개 판용 키 하나" 를 권했다. 사용자는 키를 하나도 싣지 않는 쪽을 골랐다.
값은 키 없는 사람의 한국 탭이 빈 바탕이 되는 것이다(극지 탭은 배경이 VWorld 가 아니라 상관없다). 대신 키를 하나도 싣지 않으니
공개 판의 키가 남에게 쓰일 일, 그 키의 하루 한도를 모두가 나눠 쓸 일, 키를 바꿀 때 판을 다시 구울 일이 없다.

## 3. 시험

`test_static_site` 의 브라우저 시험이 처음 뜨는 창에 가렸다(범례 단추를 누르지 못함). 다른 시험은 "나중에" 를 누른 탭처럼 열고,
창을 보는 시험 둘을 더했다 — 처음 열면 두 칸이 뜨는지, 넣은 키가 그 브라우저에만 남고 다시 열면 묻지 않는지. 구운 HTML 에
운영 VWorld 키가 없고 VWorld 가 상류에 드는지도 지킨다.

## 4. github.io 에서 잰 것

Pages 를 켠 뒤(2026-10-02 15:39) 실제 주소에서 KIGAM 키를 넣으니 `/openapi/wms` 타일 여섯 장이 200 이었다 — **KIGAM 키는 github.io
출처에서도 받힌다.** 스발바르는 NPI 지질 단위가 Sentinel-2 위에 섰다.
