# 관리 화면 "데이터소스" 탭 (P02 3 단계)

2026-10-06 · `feature/manage-sources` · jikhanjung

jikhanjung P02 의 3 단계. 명세(011)와 기록 표(012)를 엮어 관리 화면에 **데이터소스 하나가 한 줄**인 탭을 세웠다. 읽기만 한다.

## 1. 무엇을 정했나

1. **한국어 표기는 "데이터소스"** (사람, 같은 날). 계획과 코드 주석의 "자료원" 은 그대로 두고, **화면에 뜨는 글만** 바꿨다 — 탭·제목·
   머리줄·안내, 그리고 화면에 뜨는 명세 검사 문장 하나. 영어는 `Sources`
2. **"구운 자료" 탭(wetherilli 312)을 녹였다** — 그 탭이 보이던 것(있나·크기·고친 날·원본 판)은 데이터소스마다 "산출물" 칸으로 옮겼다.
   `sources.coverage()` 가 모든 `datastatus.ITEMS` 가 어느 데이터소스의 `outputs` 에 들도록 지키므로 빠지는 파일이 없다. 같은 파일이
   두 탭에 다른 이름으로 오르던 것(`fetch_pbdb` 대 `earth/pbdb.sqlite`)이 한 줄이 됐다. `manage.py data_status` 는 그대로 둔다
3. **서버가 표를 그린다** — 지난 탭처럼 템플릿이 그리고, 줄을 누르면 펼쳐지는 지난 차례(최근 20)도 미리 싣는다. 49 곳 × 20 줄이라
   작고, 새 주소(JSON)를 내지 않아도 된다
4. **늦음** — 명세의 주기로 가른다(매시 3 시간·매주 9 일·매달 40 일, `sources.LATE_HOURS`). 사람이·한 번은 늦지 않는다. 기록이
   아예 없는 것은 늦음이 아니라 **"기록 없음"** 이다. 마지막 차례가 `fail` 이면 깨짐. 늦거나 깨진 줄은 붉은 띠
5. **센 수 대 받은 수** — 기록 표에 둘이 있으면 적고, 받은 수가 모자라면 붉게(상류가 일부만 준 것)
6. **어림한 줄**(`sources_backfill`)은 `~` 를 붙인다
7. **healthz 에 수** — `sources: {total, late, failed, unknown, invalid}`. **상태는 바꾸지 않는다** — 매시 일이 늦으면 이미 `hourly`
   쪽이 상태를 낮춘다. 여기서 호스트가 남긴 기록(`hourly_status.json`)을 장부로 옮겨 적는다 — healthz 를 부르는 순찰이 있으니 따로
   cron 을 두지 않는다
8. **읽기는 장부 파일을 만들지 않는다** — 화면이 장부를 읽기만 해도 `store.sqlite` 가 생겨 시험이 저장소 뿌리에 파일을 남겼다. 파일이
   없으면 빈 것, 옮겨 적기는 기록이 꺼져 있으면(시험) 하지 않는다
9. 휴대폰에서는 카드로 — #364(wetherilli 369)의 저장 탭과 같은 틀. 데스크톱은 "주기"·"된 때" 칸을 꺾지 않는다(처음엔 "사람이" 가 한 글자씩 꺾였다)

## 2. 버린 것

- **"구운 자료" 탭을 남겨 두기** — 같은 파일을 두 곳에서 보게 된다
- **지난 차례를 누를 때 받기(JSON 주소)** — 작아서 미리 싣는 편이 단순하다. 줄이 크게 늘면 그때
- **늦으면 healthz 상태를 낮추기** — 사람이 부르는 데이터소스가 대부분이라 "늦음" 이 없고, 매시 일은 이미 낮춘다
- "지금 받기" 단추 — 사람이 정했다(처음엔 두지 않는다)

## 3. 확인

- 시험 — 늦음·깨짐·센 수(`Overview`), 관리 화면에 데이터소스 탭·"구운 자료" 탭 없음·센 수·영어판·절대 경로 안 냄, healthz 의 수,
  휴대폰에서 카드로 서고 눌러 펼쳐진다(`test_mobile`), 상자 제목이 꺾이지 않는다. 전체 2 065 개 통과(휴대폰 시험은 CI)
- 운영 파일을 읽기만 하며(장부·명세는 임시 자리) 데스크톱·휴대폰을 찍어 봤다 — GFS·GMGSI 는 매시 기록이 옮겨 적혀 `ok`, ERA5·ECCO2 는
  어림한 `~`, 판 목록·지명(저장소에 굽는 것)은 "기록 없음"

## 4. 검토 뒤에 고친 것 (#373, koprifossillab 의 검토, 같은 날)

1. **장부의 글이 걸러지지 않고 떴다** — `note` 는 명령 출력의 마지막 줄이나 예외 글이라 `/srv/GSM/db/…` 경로나 상류 주소(쿼리의 키 따위)가
   섞인다. 관리 화면은 계정을 묻지 않는다. `fetchlog.shown()` 이 화면에 내기 전에 `key=`·`whoami=` 따위 값을 지우고, settings 의 자료 자리는
   `<DB 옆>`·`<EARTH_DIR>` 꼴로, 그 밖의 절대 경로는 이름만 남긴다. 주소 안의 경로는 두었다 — 어디서 받았는지는 보여야 한다
2. **healthz 가 부를 때마다 장부에 썼다** — 공개 GET 마다 쓰기 트랜잭션이고, 명령이 장부를 잡으면 10 초 막힌다(`release.sh` 의 timeout).
   healthz 는 읽기만 한다. 옮겨 적기는 `hourly.sh` 가 차례 끝에 컨테이너의 `sources_log --sync-only` 로 — 주간 백업이 `docker compose exec`
   로 컨테이너 명령을 부르는 것과 같은 길이다. 관리 화면은 그대로 열 때 옮겨 적는다
3. **말을 하나로 — "데이터소스"** (사람이 정함). 코드·주석·로그·CLAUDE.md·HANDOFF 의 "자료원" 을 바꾸고, CLAUDE.md 의 말 표에
   `데이터소스 | 자료원`, 영어 표에 `source` 를 더했다. 옛 탭의 쓰이지 않는 영어 줄(`"구운 자료"`·`"원본 판": "Source version"` 따위)은 지웠다 —
   source 가 두 뜻이 되지 않게. 지난 devlog 의 제목과 `docs/외부_자료원.md` 같은 파일 이름은 그날의 기록이라 두었다
4. **밖에 연 판에서도 연구실 내부용이 보였다** — `GSM_PUBLIC` 이면 `lab_only` 줄을 뺀다(수에서도)

남긴 것 — 영어판에 코드 값(`ok`·`hourly`·`backfill`)과 장부의 한국어 고정 문장이 그대로 뜨는 것, 늦음 판정의 빈틈(된 적 없는 매시·`skip`·
시간대), 화면 한 번에 데이터소스마다 여는 연결. 지금 크기(49 곳)에서는 견딘다
