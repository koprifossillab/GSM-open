# 점묶음·개인 레이어·연결 레이어를 지역 쉰에서 써 보다 — 깨진 곳은 없었다

2026-10-05 · `fix/user-layers` · wetherilli

판 세션이 맡긴 일이다 — 지역이 쉰으로 늘며 캐나다 람베르트(3978)·극 평사도법(3413·3031) 탭이 늘었다. 내 자료를 얹는 세 흐름이 새 투영에서도 맞게 도는지 headless Chromium 으로 열어 보았다.
개발 서버(씨앗을 넣은 새 DB)에서 했다.

## 본 것과 결과

| 흐름 | 한 것 | 결과 |
|---|---|---|
| 점묶음 | 점 하나짜리 점묶음 여섯(오타와·앵커리지·롱이어비엔·맥머도·누크·리마)을 만들고 캐나다·미국·북미(3978)·스발바르·북극·그린란드(3413)·남극(3031)·페루·남미(3857) 탭에서 "범위를 맞춘다" | 보던 자리가 그 점에서 **0.001° 안**. 페이지 오류 없음 |
| 점묶음 CSV | 여섯을 `csv/` 로 | 지각 두께 열이 붙는다. 극지·적도 모두 |
| 점묶음 파일 올리기 | CSV 세 줄(캐나다) | 3 점 |
| 몸 | 달·화성 점묶음을 만들고 몸마다 목록 | 지구 여섯·달 하나·화성 하나·수성 없음 — 섞이지 않는다. 달 CSV 도 받힌다(개발 기계에 달 원도가 없어 단위 열은 없다) |
| 개인 레이어 | 관리 화면에서 GeoJSON 둘(캐나다 점·남극 면)을 들여와 캐나다·북미·남극·한국 탭에서 "범위를 맞춘다" | 제자리(남극 면은 위경도 네모의 가운데가 극 평사도법에서 0.3° 비켜 서는 것뿐). 페이지 오류 없음 |
| 연결 레이어 | 이 기계의 포트 하나에 양식 파일을 열고(`GSM_LINKED_ALLOW=127.0.0.1`) 관리 화면에서 잇기 | CORS 가 없어 **우리 서버를 거쳐** 받았고(`linked.py`), 북극·스발바르·그린란드(3413)에서 두 점의 범위로 맞는다 |

화면 코드도 훑었다 — `ol.proj.fromLonLat`·`toLonLat`·`transformExtent` 를 투영 없이 부르는 곳이 없다(첫 화면의 한국 기본값 하나뿐이고 곧 지역의 것으로 바뀐다).

## 남긴 것 — 시험

다음에 투영이 늘어도 깨지면 알게, 점묶음을 3978·3413·3031·3857 탭에서 맞추는 시험을 **휴대폰 화면 시험(`test_mobile.py`)** 에 더했다 — CI 의 "휴대폰 화면" job 이 브라우저로 돈다.
점묶음은 탭마다 하나만 둔다 — 넷을 한꺼번에 두니 화면이 덩이를 한꺼번에 묻고 시험 서버의 메모리 sqlite 가 스레드끼리 부딪혔다(`InterfaceError`). 운영의 파일 DB 와는 상관없는 시험 환경의 일이다.
