# 009 — 주소·장소로 찾기

2026-09-27

## 왜 VWorld 인가

지오빅데이터 플랫폼의 지도 화면에도 검색이 있지만 빗나가는 일이 잦다.
들여다보니 그 화면은 **TerriaMap**(호주에서 만든 지도 틀)이고, 검색은
기본값 그대로 **Bing 지오코더**에 걸려 있었다. Bing 은 한국의 도로명·지번·
읍면동에 약하다. VWorld 는 국토지리정보원 자료라 이 셋이 정확하고, 열쇠는
배경지도 때문에 이미 있었다.

2026-09-27 에 쏴 본 것 — "대전광역시 유성구 과학로 124" 는 좌표 하나로,
"한국지질자원연구원" 은 대전 본원·원주 분원이 따로, "가정동" 은 대전과
인천이 둘 다 나왔다. 좌표 → 주소도 된다 (지질박물관 자리에서
"과학로 124 (가정동,지질박물관)"). 한 번 찾는 데 0.13 초.

## 검색 칸은 하나다

화면 아래의 좌표 칸을 넓혔다. **좌표가 먼저다** — 넣은 것이 좌표로 읽히면
(`coords/parse/`) 곧장 가고, 아니면 주소·장소로 찾는다. 칸을 둘로 가르면
사람이 "이건 어느 칸이지" 를 먼저 골라야 한다.

찾을 때는 **행정구역·도로명·지번·장소 넷을 한꺼번에** 묻는다. 넣은 글자가
어느 것인지 우리가 가르려 들면 틀린다 — "갑천" 은 면 이름이고 도로 이름이고
하천 이름이다. 넷을 스레드로 나란히 물어 기다리는 시간은 하나 묻는 만큼이다.

**곧장 가지 않고 목록을 띄운다.** 가정동이 둘, 연구원이 셋이다. 첫째로
가 버리면 절반은 엉뚱한 곳에 떨어진다. 목록에서는 넣은 말로 **끝나는**
행정구역을 맨 앞에 둔다 — "유성구" 를 찾았는데 유성구의 동들이 먼저 뜨면
안 된다. 이름이 같은 것은 하나로 친다 — 연구원 캠퍼스처럼 한 번지에 건물이
여럿이면 같은 도로명이 건물마다 따로 온다.

## 왜 서버를 거치나

VWorld 의 검색 API 는 JSONP 로 브라우저가 곧장 부를 수도 있다 (004). 그래도
서버의 `vworld.py` 를 거치게 했다.

- **캐시에 담는다.** 주소는 지질도보다도 드물게 바뀐다. 타일과 같은 캐시
  (007)에 `.json` 으로 둔다. 좌표 → 주소는 소수 다섯째 자리(약 1 m)에서
  잘라 묻는다 — 같은 노두를 두 번 누르면 두 번째는 VWorld 를 타지 않는다
- **JSONP 는 남의 스크립트를 페이지에 끼워 넣는 일이다.** 받는 쪽이 무엇을
  돌려주든 우리 페이지에서 돈다
- 오류 문구를 영어판에 맞출 수 있고, VWorld 가 바뀌면 고칠 자리가 하나다

그래서 CLAUDE.md 의 "`kigam.py` 가 유일한 문" 을 "상류마다 문이 하나" 로
고쳤다. 두 문은 서로를 타지 않는다 — 주소 검색은 KIGAM 을 거치지 않는다.

바다처럼 주소가 없는 자리면 줄을 두지 않는다.
