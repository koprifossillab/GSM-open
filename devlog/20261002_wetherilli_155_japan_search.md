# 일본의 찾기 칸 — 국토지리원 주소·지명 검색을 브라우저가 곧장

2026-10-02 · `feature/japan-search` · wetherilli

일본 탭의 좌표 칸은 좌표로만 갔다. 한국(VWorld)·극지(지명)처럼 이름을 쳐서 가게 했다.

## 무엇을 부르나

- `msearch.gsi.go.jp/address-search/AddressSearch?q=` — 지리원 지도(地理院地図)의 찾기 칸이 쓰는 것. 주소와 지명(山·湖 따위)을
  함께 찾아 GeoJSON 점 목록을 준다. 열쇠가 없다
- **이용 조건** — 공개 API 로 문서화된 것이 아니다. 국토지리원은 2015 년 GitHub 질문(gsi-cyberjapan/gsimaps#29)에 "지리원 지도에서
  쓰는 것을 생각한 것이라 늘·오래 줄 수 있다고 장담하지 못하고, 사양이 예고 없이 바뀔 수 있다" 고 답했다. 막지는 않았다.
  주소 쪽은 도쿄대 CSIS 의 Simple Geocoding 을 쓴다고 했다. 국토지리원 콘텐츠 이용 규약은 타일을 다루고 이것은 다루지 않는다
- 그래서 **사람이 칠 때만** 부른다. 미리 데우거나 모아 두지 않는다. 닫히면 찾기가 "찾지 못했다" 를 내고 좌표는 그대로 간다

## 문을 늘리지 않았다

- CORS 가 `Access-Control-Allow-Origin: *` 다. 열쇠도 없어 감출 것이 없다 — 일본 배경 타일(지리원 타일)처럼 브라우저가 곧장 부른다
- 문(`gsi.py` 같은 것)을 거치면 우리 서버가 남의 무료 API 를 대신 부르는 꼴이 되고, 서버 IP 하나에 모든 사람의 찾기가 몰린다
- 찾은 목록은 한국 찾기와 같은 칸·같은 꼴(`renderResults`) — 갈래 "주소·지명", 맨 밑에 출처 한 줄

## 동아시아 탭은 그대로

- 동아시아는 VWorld 찾기를 쓴다(한국을 품었다). 두 찾기를 한꺼번에 돌려 섞는 길은 미뤘다 — 일본 이름을 한글로 치면 VWorld 도
  국토지리원도 못 찾고, 한자로 치면 VWorld 가 엉뚱한 한국 지명을 낸다. 섞는 법을 따로 정해야 한다

## 확인

- 임시 서버와 헤드리스 Chromium 으로 일본 탭에서 富士山(목록 → 골라 그 자리로)·東京都千代田区丸の内1·좌표를 쳐 보았다. 이 서버의
  망은 극지연구소 TLS 가로채기가 있어 헤드리스 브라우저가 인증서를 믿지 않는다 — 시험에서만 인증서 검사를 껐다. 사람의
  브라우저는 극지연구소 인증서를 믿으므로 상관없다
- 한 번은 같은 물음이 20 초 넘게 걸렸다가 다음에는 0.5 초였다. 느릴 때가 있다
