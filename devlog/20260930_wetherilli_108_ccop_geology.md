# 동·동남아시아 — CCOP 200만 지질도

2026-09-30 · `feature/ccop-geology` · wetherilli

TODOs "노는 자료" 의 "GSJ 새 호스트" 가운데 첫 건이다. CCOP(동·동남아시아 지구과학 조정위원회)의 1:200만 지질도(기반암·표층·연대를
합친 판)를 중국 탭에 둔다. 동아시아 묶음 탭에서도 보인다. 밖에 열 때 geo3al(연구실 내부용, 025)을 대신할 후보로 적혀 있던 것이다.

## 1. 상류

- `ows.gsj.jp/ows/GSJ_CCOP_Combined_Bedrock_and_Superficial_Geology_and_Age/wms` — GSJ 가 2024-05 에 옮긴 새 호스트의 MapServer.
  열쇠가 없다. 조건은 GetCapabilities 의 AccessConstraints — "개인·교육·연구·비상업 용도로 자유롭게". 출처는 CCOP 와 GSJ
- **CORS 가 없다** — 브라우저가 곧장 부르지 못해 `/GSM/wms/` 를 거친다. 타일은 3857 로 그대로 준다(`EPSG:900913` 과 같은 그림)
- 상류 이름은 `ccop` 로 따로 두고 **문은 `gsj.py`** 다 — 같은 GSJ 서버다. 심리스 V2 는 z/x/y 라 길이 다르다(`views._Door` 에 `gsj.CCOP`)

## 2. 속성 — 4326 에서만, HTML 로만

2026-09-30 에 찔러 본 것.

- 3857 로 물으면 "Search returned no results". `text/plain` 도 비고, `application/json` 은 받지 않는다(오류). `text/html` 만 표를 준다
- 4326 이라도 **네모가 작으면 비어 온다** — 0.2° 에 256 픽셀도 없다. 1° 에 101 픽셀이면 온다. 200만 축척 판이라 더 가까운 축척에서는
  속성을 내주지 않는 것으로 읽힌다
- 그래서 문이 화면이 보낸 `GetFeatureInfo`(3857 범위·픽셀)에서 **누른 자리의 위경도를 풀어** 그 자리를 가운데 둔 4326 의 1° 네모로
  다시 묻는다(`gsj._clicked_lonlat`, 1.3.0 의 4326 은 위도가 먼저인 것까지). 한 칸이 0.01° 라 누른 자리와 1 km 남짓 어긋날 수 있다
- HTML 표의 한 줄(`Geology | J_Pf: Felsic Plutonic Rocks, Jurassic`)을 지질기호·암석·지질시대로 나눈다. 시대는 한국어판에서 ICS
  한글판으로 옮긴다(쥐라기). 서울은 쥐라기 규장질 심성암(J_Pf), 청두 쥐라기 퇴적암, 방콕·도쿄 제4기 퇴적암
- TODOs 는 속성이 `MAJOR_CODE` 뿐이라 코드표가 들 것이라 적었다. HTML 틀은 이미 기호의 풀이(암석·시대)를 싣고 있어 코드표가 들지 않았다

## 3. 무엇을 대신하나

- 중국 탭에서 보니 **중국 서부·북부(신장·티베트·내몽골)가 비어 있다** — CCOP 회원국의 자료를 이은 판이라 덮는 범위가 그렇다.
  그래서 geo3al 을 그대로 대신하지는 못한다. 동부 중국·한반도·일본·동남아시아는 덮는다. 밖에 열 때는 geo3al 을 내리고 이것을 두면
  서부가 빈다는 것을 사람이 알고 정한다
- 연구실 내부용(`LAB_ONLY`)에 넣지 않았다 — 비상업 연구 용도는 조건 안이다
