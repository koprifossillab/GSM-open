# 팝업이 가운데 맞춤 없이 서던 것 — 휴대폰 시험이 가끔 깨진 까닭

2026-10-05 · `fix/mobile-popup` · wetherilli

#289 의 CI 에서 `test_팝업이_화면_안에_선다` 가 "`#popup` 가 오른쪽으로 나간다(411 > 391)" 로 깨졌다가 다시 돌리니 통과했다.
시험이 흔들린 것인지 화면이 정말 넘친 것인지부터 갈랐다.

## 잰 것

같은 장면(한국 탭 가운데의 점을 누른다)을 열두 번 되풀이하며, 팝업이 뜬 뒤 2.5 초 동안 50 ms 마다 팝업의 왼쪽·오른쪽 끝을 적었다.

| | 뜬 틀 | 250 ms 뒤 | 끝 |
|---|---|---|---|
| 고치기 전 (12 번 모두) | 195 → 515 (오른쪽으로 125 px 넘침) | 105 → 425 … | 58 → 378 |
| 고친 뒤 (12 번 모두) | 35 → 355 | 35 → 355 | 35 → 355 |

**둘 다였다.** 화면은 뜰 때마다 정말 넘쳤고(잠깐), 지도가 끌려 와(autoPan 200 ms) 들어왔다. 시험은 600 ms 를 기다려 쟀는데 느린 CI
(swiftshader)에서는 그 끌림이 600 ms 를 넘겨, 끌리는 한가운데(411)를 잰 것이다.

## 까닭

`.popup` 이 `position: absolute` 였다. OpenLayers 가 팝업을 감싼 겹(`.ol-overlay-container`)은 안의 것이 `absolute` 이면 크기가 0 이 되고,
`positioning: "bottom-center"` 의 가운데 맞춤은 그 겹을 제 크기의 −50 %·−100 % 옮기는 것이라 아무것도 옮기지 않는다. 그래서 팝업은
**누른 자리를 왼쪽 위 모서리로 삼아 오른쪽 아래로** 늘어졌고, 화면 밖을 본 OpenLayers 가 지도를 끌어 왔다. 데스크톱에서도 같았다 —
넓어서 지도가 덜 끌렸을 뿐이다.

## 고친 것

- `.popup` 을 `position: relative` 로 — 겹이 팝업 크기를 따라 가운데 맞춤이 먹는다. 팝업은 이제 누른 점 바로 위 가운데에 선다
  (오프셋 −8 px 이 처음부터 그 뜻이었다). 닫기 단추의 기준(`absolute`)도 팝업 그대로다
- 끌어오기는 **지도가 팝업을 그린 다음에**(`panPopup` — `postrender` 다음 틀) 한다. Overlay 의 `autoPan` 은 뺐다 — 자리를 옮긴 그 순간의
  사각형으로 끌기 때문이다. 속성이 늦게 차 팝업이 자랄 때·장미도가 붙을 때도 같은 `panPopup` 을 부른다
- 시험은 **줄이지 않고 늘렸다** — 팝업이 뜬 그 틀(두 틀 뒤)에도 화면 안인지 보고, 600 ms 뒤에 한 번 더 본다. 고치기 전의 코드라면
  첫 검사가 늘 깨진다(뜬 틀이 195 → 515)

## 버린 것

- 시험의 기다림만 늘리기(600 → 1 500 ms) — 깨짐은 없어지지만 화면이 뜰 때마다 넘쳤다 들어오는 것은 그대로 둔다
- 팝업 자리를 JS 로 직접 셈하기 — OpenLayers 의 자리 잡기가 CSS 하나로 제대로 돈다
