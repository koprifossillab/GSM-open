# 영어판 새는 곳과 온 지구의 무게

2026-10-05 · `fix/en-leaks` · wetherilli

판 세션이 준 일 — 영어판으로 지역 탭 몇·온 지구·달·화성·수성·관리 화면을 열어 한국어가 새는 곳을 고치고, 온 지구에 레이어를 서른 넘게 켰을 때
느려지는 곳을 재어 쉽게 줄일 것은 줄인다.

## 영어판 — 어떻게 찾았나

개발 서버(사본 DB)를 띄우고 Playwright 로 `gsm_lang=en` 쿠키를 건 채 열두 화면(지역 다섯·3D·온 지구·달·화성·수성·관리·소개)을 열어, **보이는 글 마디마다
한글이 든 것**을 모았다. 설정 창·판 이력·지역 차림도 열어 보았다. 상류는 끊었다.

일부러 둔 것은 뺐다 — 한국어 이름(`대돌여지도`, 구 화면의 `대돌여지도 · 온 지구` 밑줄 — 영어판은 이름의 짝을 뒤집어 한국어를 밑에 둔다), 언어 고르개(`한국어`),
점묶음 올리기 안내의 열 이름(`위도`·`경도` — 사람이 그 글자로 적은 열을 알아본다), 판 이력(CHANGELOG 은 옮기지 않는다).

## 새던 것

| 자리 | 무엇 | 고침 |
|---|---|---|
| 3D 의 지형 출처 | `국토지리원` | `T("국토지리원")` → GSI Japan |
| 3D 의 지질 레이어 출처(기본값) | `© 한국지질자원연구원` | `T()` → © KIGAM |
| 관리 화면 "구운 자료" 칸 | `(손으로 둔다)`(312 에서 내가 넣었다) | `datastatus.MANUAL = msg(…)`, 화면·명령이 옮긴다 |

알림 타일은 처음부터 영어다(`GSM: no API key` 따위). 팝업 이름표는 문들의 `("한국어", 값)` 꼴을 긁어 `PROP_EN`·`EN` 에 없는 것을 찾았는데, 남은 것은 로그 문장·
관리자 칸 이름·자료의 원래 값(KIGAM 5만 구조 요소의 이름은 원값과 짝을 이루는 `msg` 가 따로 있다)뿐이었다.

**다시 새지 않게** — 휴대폰 시험의 영어판(`test_영어판`, 지역 지도·온 지구)에 보이는 한국어를 찾는 검사를 더했다(`HANGUL_LEAKS`, 위의 일부러 둔 것만 뺀다).
CI 의 휴대폰 job 이 돈다.

## 온 지구의 무게 — 쉽게 줄일 곳은 없었다

운영의 온 지구 파일(`/srv/GSM/db/earth`·바람·해류)을 읽기만 하여 개발 서버에 물려 레이어 마흔넷을 다 켤 수 있게 하고 쟀다.

- **켜고 끄기** — 하나 켤 때 동기 시간 2–10 ms(한 번 36 ms), 마흔넷째에도 늘지 않는다. 켤 때마다 패널을 다시 짓지만 무겁지 않다
- **그림** — 한 화면에 레이어마다 칸 8 남짓, 마흔넷이면 350 장이다. 같은 주소를 다시 묻는 것(폴링)은 없었다 — 20 초 동안의 요청 92 가 모두 다른 칸이었고,
  처음 채우기가 브라우저의 한 호스트 여섯 연결과 개발 서버의 빠르기에 막혀 늦게 끝나는 것이다. 처음 잴 때 그림을 끊었더니 지도가 실패한 칸을 거듭 다시 물어
  폴링처럼 보였다 — 그림을 받게 하고 다시 쟀다
- **긴 작업** — 구는 소프트웨어 WebGL(이 기계·CI)에서 20 초에 1 초 남짓, 평면은 한 번 2.5 초짜리가 섰다(레이어 마흔넷의 합성으로 본다). GPU 가 있는 사람의
  브라우저에서는 다르다 — 여기서는 원인을 가르지 못했다

"쉽게 줄일 것" 은 없다고 본다. 줄이려면 레이어 여럿을 서버에서 한 장으로 합성하거나 켤 수 있는 수를 묶어야 하는데, 둘 다 쓰는 법이 바뀐다. 적어만 둔다.
