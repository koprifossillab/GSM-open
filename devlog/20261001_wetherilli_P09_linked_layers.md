# 연결 레이어 — 남의 API 를 개인 레이어로 잇는다 (계획)

2026-10-01 · `feature/linked-layers` · wetherilli

사람이 정한 것 — 다른 사이트가 우리 양식(P08)으로 맞춘 API 주소와 인증키를 주면, 그 자료를 우리 지도에 얹어 본다.

## 갈림길에서 정한 것

- **누가 부르나 — 둘 다.** 브라우저가 먼저 곧장 부르고, 상대가 CORS 를 열지 않아 막히면 우리 서버를 거친다.
  VWorld 배경을 그렇게 했다(033). 대부분의 기관 API 는 CORS 를 열지 않으므로 서버 길이 없으면 쓸 데가 적고,
  CORS 를 연 곳까지 서버를 타게 하면 우리 서버가 쓸데없이 중계가 된다
- **주소와 키는 그 브라우저에만** — 개인 레이어와 같다. 서버는 받은 것을 넘겨줄 뿐 적지 않는다. 관리자가 등록해
  모두가 보게 하는 길(상류 레이어처럼)은 로그인이 생겨야 해서 미뤘다
- **지도를 열 때마다 새로 받는다** — 마지막으로 받은 것은 브라우저에 두어, 상대가 멈춰도 옛것을 보인다. 보는 범위만
  묻는 bbox 길은 상대가 bbox 를 받아야 해서 뒤로
- **키를 싣는 꼴은 고른다** — 없음·Bearer·머리(이름)·주소(?이름=키). 기관마다 다르다

## 서버 길의 위험

이 문(`linked.py`)만은 주소를 우리가 정하지 않는다. 우리 서버는 연구실 망(phyloserver·NAS·MySQL)에 닿으므로,
남이 그 주소를 넣으면 우리 서버가 디딤돌이 된다(SSRF). 그래서

- http·https, 포트 80·443·1024 위만
- 호스트를 풀어 **공인 주소가 아니면 거절**. 연구실 안의 API 는 운영자가 허락 목록에 적는다
- **검사한 IP 로만 붙는다** — 검사와 연결 사이에 DNS 를 바꾸는 것(rebinding)을 막는다
- 넘겨주기마다 다시 검사, 다른 호스트로 넘어가면 키를 싣지 않는다
- 20 MB · 20 초 · 1 분 30 번. 밖에 연 뷰어(`GSM_PUBLIC`)에서는 닫는다 — 아무 공인 주소나 대신 받아 주는 중계가 된다

## 뒤로 미룬 것

- 관리자가 등록해 모두가 보는 연결(서버에 키를 두는 길)
- bbox 로 보는 범위만 묻기, 쪽 나누기(paging)
- 정해진 간격으로 다시 받기 — 지금은 열 때와 사람이 누를 때
