# 연결 레이어 — 곧장 받고, 막히면 서버를 거치고, 못 받으면 옛것

2026-10-01 · `feature/linked-layers` · wetherilli

계획은 P09. 여기는 만들며 고른 것.

## 받는 길

`personal.js` 의 `fetchLinked` 가 브라우저에서 곧장 `fetch` 한다. **막힌 것(TypeError — CORS·망)만 서버로 돌린다.**
상대가 답을 했는데 401·500 이면 서버로 가도 같으므로 그대로 실패다. 서버(`POST linked/fetch/`)는 받은 바이트를 풀지 않고
넘긴다 — 읽는 것은 여전히 `personal.js` 하나다. 양식 읽기가 서버·브라우저 두 벌이 되면 "관리 화면에서는 되는데 서버를
거치면 다르다" 가 생긴다.

곧장 해 보다 CORS 로 막혀도 요청 자체는 상대에게 간다. 그래서 CORS 를 열지 않은 상대에게는 같은 요청이 두 번 간다.
"곧장 안 되던 곳" 을 기억해 두면 줄일 수 있지만, 상대가 나중에 CORS 를 열면 영영 서버를 타게 된다. 한 번 더 가는 쪽을 골랐다.

## 서버 문 — 검사한 IP 로만 붙는다

`linked.py` 는 호스트를 풀어 모든 주소가 공인인지 본 뒤, 그 IP 로 붙는다. requests 는 연결할 때 이름을 다시 풀기 때문에
그대로 두면 검사와 연결 사이에 DNS 를 사설 주소로 바꿀 수 있다(rebinding). 어댑터의 연결 함수(`_new_conn`)만 갈아 끼워
`(검사한 IP, 포트)` 로 붙게 했다. TLS 의 SNI·인증서 검사와 Host 머리는 호스트 이름 그대로라 https 도 그대로 돈다(api.github.com
으로 확인). urllib3 의 `_dns_host` 를 IP 로 바꾸는 길도 보았으나 그것은 `host` 와 묶여 있어 인증서 검사가 IP 로 간다.

- IPv4 를 먼저 고른다 — 이 서버는 IPv6 길이 없어, 풀린 순서대로 고르면 가끔 닿지 못했다
- `trust_env = False` — 환경의 프록시를 타면 붙는 곳이 검사한 IP 가 아니게 된다
- 사용량은 `usage.record("linked", …)` 로 세되 차단 조짐(`blocked`)으로는 넘기지 않는다. 그 표지는 **모든 상류를 10 분 쉬게**
  하므로, 남의 API 가 403 을 낸다고 KIGAM 타일까지 멈추면 안 된다
- 오류 문장은 `msg()` 로 감싸 영어판에서 옮긴다. `test_i18n` 이 `linked.py` 도 긁는다

## 기록과 화면

- 기록에 `link`(주소·방식·이름·키)·`fetched`·`status`(받은 길 또는 못 받은 까닭)를 더했다. **받아 덮을 때 사람이 고친 이름·색·
  이름표는 둔다.** 키는 `toGeoJSON`·`toCSV` 에 실리지 않는다(시험이 본다)
- 지도는 저장소의 것을 먼저 그리고, 열 때 한 번 새로 받아 바꿔 그린다. 다른 창의 알림으로 다시 읽을 때는 받지 않는다 —
  받으면 저장, 저장하면 알림, 알림이면 다시 받기로 돈다
- 관리 화면 — 반입 탭에 "API 로 잇기"(받아 본다 → 읽은 것 → 저장), 저장 자료에 연결 표·⟳ 새로 받기·연결 고치기
- 목록의 수 옆에 🔗, 못 받았으면 "받지 못해 옛것" 을 붉게

## 해 보니

가짜 상대 둘(127.0.0.1:8821, 허락 목록에 넣고)을 띄워 headless Chromium 으로 돌렸다 — CORS 를 열고 `X-API-Key` 를 묻는 곳은
**곧장**, CORS 없이 `?apikey=` 를 묻는 곳은 **서버를 거쳐**, 틀린 키는 "거절했다 (401) — 인증키를 본다". 상대를 내린 뒤 지도를
열면 옛것 2 점을 그리고 "받지 못해 옛것". 서버 로그에 키는 남지 않았다.
