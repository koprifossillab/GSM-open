# CI 를 두 번 돌리지 않는다 — 개발 저장소를 비공개로 돌리기 전에

2026-10-20 · `fix/ci-minutes` · wetherilli

사용자: 「gsm의 사내용 repo를 이제 private로 돌리고 싶어」. 공개 저장소의 Actions 는 시간을 세지 않지만 비공개는
월 할당량(Free 2 000 분·Pro 3 000 분)에 걸린다. 지난 한 달에 `시험` 이 400 번 남짓 돌았고 번마다 9 분쯤
(뷰어 시험 2·휴대폰 화면 6·이미지 굽기 1)이라 3 600 분 남짓이었다. 넘기면 CI 가 멈추고 PR 병합 조건이 막힌다.

## 무엇을 뺐나

- **main 의 push 에서 휴대폰 화면·이미지 굽기를 뺐다.** PR 에서 이미 본 것을 병합 커밋에서 또 본다. 휴대폰 화면이
  가장 비싸다(6 분). "뷰어 시험" 만은 남겼다 — 병합한 결과가 정말 도는지는 main 에서 본다
- **문서·기록만 고친 main 커밋은 건너뛴다**(`paths-ignore` — `devlog/`·`docs/`·`*.md`). CLAUDE.md 가 그런 커밋을
  main 에 바로 올리라고 한다. PR 쪽에는 걸지 않았다 — 필수 검사가 돌지 않으면 병합이 막힌다. 태그의 push 에는 경로
  거르기가 걸리지 않으니 판의 시험·이미지는 그대로다
- **같은 PR 에 새로 밀면 앞의 것을 멈춘다**(`concurrency`). main·태그는 돌기 시작한 것을 멈추지 않는다 — 판을 붙이는
  태그의 이미지가 중간에 끊기면 안 된다. 기다리는 것은 그룹마다 마지막 하나만 남는데, 뒤의 것이 앞의 코드를 덮으니 괜찮다
- **PR 에서도 휴대폰 화면·이미지 굽기는 그쪽 파일이 바뀔 때만 돈다**(2026-10-20 두째). 비공개로 돌린 뒤 관리자 계정이 센
  10 월이 1 048 번·4 000 분 남짓이었고 병합한 PR 만 300 개가 넘는다. main 의 push 를 줄여도 PR 쪽이 할당량을 넘긴다.
  휴대폰 화면(5.4 분)은 화면 파일(`static/`·`templates/`·그 시험·정적 판)이, 이미지(1 분)는 `deploy/`·requirements 가
  바뀔 때만 본다. 가리는 것은 뷰어 시험의 첫 걸음(`dorny/paths-filter`)이다 — job 을 따로 두면 그것도 1 분으로 센다.
  휴대폰 화면은 뷰어 시험 뒤로 미뤘다(`needs`) — 앞이 깨지면 비싼 뒤는 돌지 않는다. 워크플로를 둘로 가르지 않은 것은
  `release.sh` 가 태그의 실행 하나만 보기 때문이다. **태그에서는 다 돈다** — 파이썬만 고친 PR 이 화면을 깨도 판에서 잡힌다.
  132 가 지키던 것을 PR 마다에서 판마다로 늦춘 셈이고, 그 값을 받아들였다
- 휴대폰 화면의 `EmbedApi.test_위경도_고르기` 가 느린 러너에서 129.04 를 냈다 — 패널을 접은 뒤 지도 칸이 600ms 안에 다
  안 바뀌어 가운데를 잘못 눌렀다. 칸이 멈출 때까지 기다리고 다시 맞춘 뒤 누른다

## 버린 것

- **self-hosted runner** — 시간은 안 들지만 운영 서버에서 시험을 돌리게 된다(저장소가 비공개라 남의 PR 은 없다).
  줄이고도 모자라면 그때 사람이 정한다
- 휴대폰 화면을 PR 에서도 손으로만 부르기 — 지켜 온 검사(132)를 사람이 잊으면 그대로 빠진다
