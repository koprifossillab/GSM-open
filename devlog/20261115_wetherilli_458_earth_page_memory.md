# 온 지구 화면이 자료를 통째로 붙들지 않게

2026-11-15 · `fix/earth-page-memory` · wetherilli

같은 이미지로 뜬 두 컨테이너의 메모리가 두 배 넘게 달라 까닭을 봤다. 기동 직후는 같았다. 받은 요청을 새 프로세스에서 그대로 되돌려 보니
**온 지구 화면(`earth/`) 한 번에 일꾼의 메모리가 60 MB 는다** — 타일 수천 장은 거의 늘리지 않았다.

화면을 그릴 때 레이어마다 "구운 것이 있는가" 를 묻는데, 그 물음이 파일을 통째로 읽어 `lru_cache` 에 붙들었다.

| 물음 | 읽던 것 |
|---|---|
| `faults.available()` | 세계 활성단층 — 17 MB |
| `paleocoast.ages()` | 옛 해안선의 고리 전부 — 9 MB |
| `tectonics.available()` | 판 경계·지질구 — 7 MB |
| `icemargins.stops()` | 빙상 가장자리의 조각 전부 — 6 MB |
| `impacts.available()` | 충돌구·LIP — 4.5 MB |

화면이 그 레이어를 켜지 않아도, 일꾼마다 따로 든다.

## 고친 것

- **있는가는 파일이 있는지로 답한다**(`os.path.isfile`) — 단층·판 경계·충돌구. 범례는 코드의 표라 자료가 필요 없다
- **연대만 뽑고 버린다** — 옛 해안선의 시점, 빙상 가장자리의 연대. 파일의 때를 열쇠로 한 번 읽어 연대만 남긴다
- 타일을 그리는 길은 그대로다 — 그때 `data()`·`load()` 가 읽어 붙든다. 쓰는 일꾼만 값을 치른다

같은 조건에서 재니 화면 한 번에 +60 MB 가 +16 MB 가 됐다. 남은 16 MB 는 화산 목록·지각·암상 격자와 처음 불리는 모듈들이다 — 작아서 두었다.

## 버린 것

- 굽는 쪽이 연대를 따로 적어 두는 것(곁 파일) — 읽지 않고 답할 수 있지만 운영의 파일을 다시 구워야 하고, 연대만 뽑는 값이 한 번뿐이라 얻는 것이 적다
- gunicorn 의 `max_requests` 로 일꾼을 갈아 띄우기 — 증상을 가릴 뿐이고, 붙든 자료가 다시 읽힌다

## 지킴

`test_page_memory` — 온 지구 화면을 한 번 연 뒤 다섯 자료의 캐시가 비어 있어야 한다. 새 레이어가 화면에서 `data()` 를 부르면 여기서 깨지지는 않는다
(그 모듈을 표에 더해야 한다) — 새 자료를 더할 때 "있는가" 가 읽지 않는지 본다.
