# 아라온호 받기가 DNS 로 22 시간 멈춘 것 — 호스트 /etc/hosts 에 고정

2026-10-06 · `main` · koprifossillab

## 1. 무엇이 있었나

`/GSM/healthz/` 가 `degraded` 였다. 매시 받기(`hourly.sh`) 가운데 `fetch_araon` 만 **2026-10-05 11:40 부터 22 시간 남짓** 잇달아
실패했다 — `live.kopri.re.kr` 의 이름을 풀지 못했다(`NameResolutionError`). 10-05 04:40 무렵에도 두 번 실패했다 풀렸다.
바람·위성 구름·최근 지진은 그동안 `ok` 였다.

## 2. 까닭

서버의 DNS 가 둘이고(`203.250.179.4`·`172.16.200.30`), **`172.16.200.30` 은 `kopri.re.kr` 을 모른다**(빈 답). 다른 쪽과
`8.8.8.8` 은 `203.250.180.137` 로 푼다. 서버가 둘을 오가다 모르는 쪽에 붙으면 멈춘다. 같은 까닭으로 KPDC 는 이미 compose 에
`extra_hosts` 로 주소를 박아 두었는데(wetherilli 095), **아라온 받기는 컨테이너가 아니라 호스트 cron(`run.sh`)에서 돌아**
그 설정을 타지 않았다.

## 3. 고친 것

사람에게 두 길을 내놓았다 — 호스트 `/etc/hosts` 에 한 줄, 또는 서버 DNS 에서 `172.16.200.30` 을 빼거나 뒤로. 사람이 앞의
것을 골라 sudo 로 넣었다:

```
203.250.180.137 live.kopri.re.kr
```

손으로 한 번 돌리니(`run.sh fetch_araon`) 2026-10-06 00:00 UTC 의 자리를 받았다.

- **잃은 것이 없다** — 위치 판은 마지막 자리 하나만 보이므로 실패한 시간의 자리는 되찾을 수 없지만, 10-04 00:00 과 10-06
  00:00 의 자리가 같다(광양항 34.9204, 127.6968). 그동안 정박해 있었다
- **약점은 KPDC 의 `extra_hosts` 와 같다** — 극지연구소가 주소를 바꾸면 조용히 깨진다. 그때도 `/healthz/` 가 `degraded` 로
  알린다. 서버 DNS 가 고쳐지면 이 줄과 compose 의 `extra_hosts` 를 함께 지운다
- 코드(`kopri.py`)에 주소를 박거나 다른 DNS 로 묻게 하는 길은 버렸다 — 상류 주소를 코드가 들고 있게 되고, 서버의 이름 풀이를
  앱마다 따로 고치는 꼴이 된다
