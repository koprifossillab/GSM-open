# 데이터소스 탭 — #373 검토의 "나중에" 넷

2026-10-06 · `fix/sources-followup` · jikhanjung

#373 의 검토(koprifossillab)가 병합 전에 셋을 고치게 하고(`18b5a11`) 넷을 "나중에" 로 남겼다. 그 넷을 묶었다.

## 1. 무엇을 정했나

1. **영어판의 코드 값** (검토 4) — 장부에는 코드 값(`ok`·`hourly`·`seed` …)과 한국어 원문을 그대로 두고, **화면이 옮긴다**.
   결과·어디서·명세를 읽은 곳마다 이름 표(`sources.RESULT_LABELS`·`ORIGIN_LABELS`·`SPEC_ORIGIN_LABELS`)를 두었다. 장부가 스스로 적는
   고정 문장 셋(마지막으로 된 차례 둘·어림)과 `명세가 바뀌었다 — {name}` 은 `fetchlog.note_text` 가 `msg` 로 돌려 옮긴다. 명령의
   말(stdout 의 마지막 줄)은 옮기지 않는다 — 속성 값처럼 자료다
   - 장부를 영어 코드로 다시 적는 길은 버렸다 — 지난 줄이 이미 한국어로 쌓였고, 서버의 `sources_log` 는 한국어로 읽는다
2. **늦음의 빈틈** (검토 6)
   - **한 번도 된 적 없는 일은 첫 차례부터 잰다** — 처음부터 깨진 매시 일이 "깨짐" 으로만 떴다. `latest()` 가 첫 줄도 준다
   - **`skip` 은 된 것으로 치지 않는다** — 쳐 주면 건너뛰기만 거듭하는 일의 늦음이 가려진다. 지금 `skip` 을 내는 일은 없다
   - **순서는 글자가 아니라 때로** — `ORDER BY julianday(started_at)`. 호스트(+09:00)와 컨테이너(UTC)의 줄이 섞이면 글자 순서가
     틀린다. 줄을 UTC 로 다시 적는 길은 버렸다 — `UNIQUE (source, started_at, origin)` 이 옛 줄과 새 줄을 다른 줄로 본다
3. **성능** (검토 7) — 지난 차례는 `history_many` 가 `ROW_NUMBER() <= 20` 질의 하나·연결 하나로(화면 한 번에 연결이 100 남짓이었다).
   healthz 는 `overview(files=False)` — 수만 쓰니 구운 파일을 stat 하지 않는다. `fetch_log` 를 줄이는 정책은 아직 — 한 해에
   매시 넷이면 3 만 5 천 줄 남짓이라 급하지 않다
4. **자잘한 것** (검토 8)
   - 산출물 칸에 datastatus 의 "무엇" 을 붙이고 "만드는 명령" 은 `title` 로 — 옛 "구운 자료" 탭이 보이던 것
   - 명세가 아예 없으면(`origin == "none"`) 빈 표 위에 `sources_seed` 를 부르라는 안내
   - 펼치는 줄에 `role="button"`·`aria-expanded`·`aria-controls`
   - 템플릿의 섹션 주석을 "데이터소스" 로. 옛 탭의 i18n 줄은 `18b5a11` 이 지웠고 `"무엇"` 은 저장 탭이 쓴다

## 2. 확인

- 시험 8 개(`Followup`) — 시간대가 섞인 순서, skip, 첫 차례부터의 늦음, `history_many` 와 연결 수, healthz 가 구운 파일을 보지 않음,
  영어판의 코드 값·고정 문장, 명세 없음 안내, aria·산출물 설명. 전체 2 085 개 통과
- 나란히 돌린 시험에서 두 번, 이 PR 과 상관없는 시험(화석·지역 점)까지 `disk I/O error` 로 깨졌다. 같은 브랜치로 다섯 번 거듭 돌려
  모두 통과했다 — 같은 때 장비에서 돈 다른 일로 본다

## 검토 뒤에 고친 것 (#375, koprifossillab 의 검토, 같은 날)

- **펼치는 것은 이름 칸의 단추로** — 줄(`<tr>`)에 `role="button"` 을 달면 낭독기가 그 줄을 단추로 읽어 표의 칸을 잃는다. 이름을
  `<button aria-expanded aria-controls>` 로 두고 Enter·Space 는 단추가 맡는다. 줄의 다른 곳을 눌러도 펼쳐지는 것은 그대로
- **만드는 명령은 펼친 줄에** — `title` 은 휴대폰에서 볼 길이 없다. 펼친 줄에 `산출물 ← 명령` 으로 적는다

## 4. 머리줄과 결과의 말 (사람, 같은 날)

"됨" 이 무엇이 됐다는 것인지 읽히지 않았다. 결과는 **성공**·실패·건너뜀으로, 두 칸의 머리줄은 **마지막 실행**(결과가 무엇이든 가장
최근 차례)·**마지막 성공** 으로 짝을 맞췄다. 그냥 "마지막" 은 "마지막 변경" 으로도 읽혔다. "완료" 도 견주었으나 실패한 차례도
끝나기는 했으니 성공·실패의 짝이 낫다. 영어는 그대로(ok·Last run·Last success)

## 5. 결과는 따로 칸 (사람, 같은 날)

"마지막 실행" 칸에 때·초·결과·센 수·마지막 말이 함께 들어 있었다. **결과(성공·실패)와 그에 딸린 것(센 수·마지막 말)은 "결과" 칸으로**
떼고, "마지막 실행" 에는 때와 걸린 초만 둔다. 칸이 일곱이 되며 표가 화면(1 040 px)보다 넓어진 것을 찍어 보고 알았다 — 실은 #375 에서
산출물 칸에 datastatus 의 판 글(GVP 레이어 이름·DOI 주소, 한 덩이 500 px 남짓)이 꺾이지 않게 들어간 탓이었다. 산출물 칸의 글을
꺾게 하고, 주기 칸("매달 첫 월요일")도 꺾게 해 1 040 px 에 맞췄다
