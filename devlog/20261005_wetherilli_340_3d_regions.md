# 3D 를 지역마다 열어 보다 — 빌려 온 레이어가 빠져 있었다

2026-10-05 · `feature/3d-regions` · wetherilli

판 세션이 "써 보며 막히는 곳을 찾으라" 했다. 3D 화면을 지역 쉰여덟(나라·묶음)마다 열어 보았다 — 개발 서버에 씨앗을 넣고 headless Chromium(swiftshader WebGL)으로
`3d/?region=…` 을 열어 고르개의 레이어 수·처음 레이어·페이지 오류를 모았다. 페이지 오류는 하나도 없었다.

## 막힌 것 — 2D 가 빌려 보이는 레이어가 3D 에는 없다

3D 는 고르개에서 **제 지역(묶음이면 품은 지역)의 레이어군만** 남긴다(050). 그런데 2D 는 지역이 다른 지역의 레이어를 **빌린다**(`REGIONS.*.borrow`) — 프랑스·독일·스페인…이
영국에 둔 EGDI 1:100만·독일에 둔 IGME5000·북극해에 둔 EMODnet 을, 남미 나라들이 콜롬비아에 둔 남미 1:500만을, 중미가 미국의 푸에르토리코를.
3D 는 이것을 몰라 **프랑스 6·네덜란드 1·에콰도르 1·파라과이 0** 개였다(2D 의 3 분의 1 남짓).

- `map3d.js` 에 2D 와 같은 빌리기 표(`BORROW`)와 같은 규칙(상류 이름, 또는 `:` 로 끝나는 레이어 이름의 앞머리)을 두었다. 빌린 레이어군은 **제 것 뒤에** 선다 —
  처음엔 앞에 서서 프랑스의 처음 레이어가 EMODnet 해저 지질이 되었다(2D 도 뒤에 둔다)
- 표를 두 벌 두는 것이라 **`test_mapview` 가 둘이 같은지 본다** — `map.js` 의 지역마다 `borrow` 를 읽어 견준다. 묶음 표(`BUNDLES`)는 이미 같았다
- 다시 열어 보니 프랑스 22·스페인 21·네덜란드 17·에콰도르 8·파라과이 7. 처음 레이어는 파라과이(없음 → 남미 1:500만) 말고 그대로다

## 하나 더 — 3D 주소를 곧장 열면 설악산

주소에도 저장소에도 자리가 없으면 어느 지역이든 설악산으로 열렸다(2D 의 3D 단추는 자리를 싣고 가므로 단추로는 드러나지 않는다). 한국이 아닌 지역은 **처음 레이어의 범위 가운데**로 열게 했다 —
프랑스 2.2°E 46.3°N 줌 5.6, 페루, 남극 70°S. 한국은 그대로 설악산이다.

## 남은 것

파나마·얀마옌은 3D 로 얹을 것이 없다(점 레이어·우리 파일의 모양뿐) — "얹을 지질 레이어가 없다" 가 뜬다. 맞는 안내다.
