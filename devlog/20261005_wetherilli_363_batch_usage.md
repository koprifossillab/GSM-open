# 상류 호출 세기에서 명령이 낸 것을 가르다

2026-10-05 · `feature/batch-usage` · wetherilli

347 에서 운영을 보다 걸렸다 — 오늘의 상류 호출 천 번이 08 시의 레이어 대조(`verify_layers`) 한 판이었다. 대조 하루는 화면 하루보다 수가 크고 캐시에 담지 않으니,
`upstream_stats` 로 화면 쓰임(메타타일의 "칸 수의 1/4", 299)을 읽을 수 없었다. 그래서 대조인지 먼저 `Layer.verified_at` 으로 걸러야 했다.

## 한 것

- `UpstreamDay.batch` — 그날 그 상류의 호출 가운데 **명령이 낸 것**. 성공·실패·차단을 가리지 않고 더한다. 마이그레이션 0047, 열에 db 기본값(299 처럼 옛 판으로 되돌려도 행이 들어가게)
- 명령인지는 **프로세스가 정한다** — `manage.py <명령>`(대조·미리 데우기·받기·shell)이면 명령, gunicorn(운영)·`runserver`(개발)·`test` 면 화면. 화면은 늘 서버 프로세스에서,
  명령은 늘 제 프로세스로 뜨므로 import 때 한 번 정하면 된다(`usage.BATCH`). 명령마다 표를 다는 길보다 빠지는 명령이 없다 — 호스트 cron 의 받기(`run.sh`)도 저절로 든다
- `upstream_stats` 에 **명령** 칸, 관리 화면의 건수 옆에 "(명령 n)". 화면 쓰임은 건수에서 그것을 뺀 것이다

## 버린 것

- **명령의 호출을 아예 세지 않기** — 차단 조짐은 누가 냈든 세야 하고(대조가 막히면 화면도 막힌다), 하루 몇 번 물었는지도 상류의 이용 조건 앞에서는 다 센다
- **명령의 호출을 다른 상류 이름(`verify:bgr`)으로** — 표가 두 배로 늘고 상류마다 합을 다시 지어야 한다
- **응답 시간을 갈라 세기** — 걸린 시간은 누가 물었든 상류의 빠르기다. 건수만 가른다
