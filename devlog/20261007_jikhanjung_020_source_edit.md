# 데이터소스 탭에서 명세를 고친다 — 탭 안의 로그인 (P03 2 단계)

2026-10-07 · `feature/source-edit` · jikhanjung

jikhanjung P03 2 단계의 하나. 명세는 1 단계부터 admin 에서 고칠 수 있었다. 사람이 "탭에서 데이터소스 정보 수정하는 기능을 만들면서 탭에
django admin 로그인 폼도" 라고 했다(2026-10-07) — 보는 자리와 고치는 자리를 한 화면에.

## 1. 무엇을 정했나

1. **로그인은 Django 계정·세션 그대로** — 탭의 폼이 `AuthenticationForm` 으로 들인다. admin 과 같은 계정이고, 탭에서 들어오면 admin 에도 들어온
   것이다. **staff 만 들인다** — staff 가 아닌 계정은 "명세를 고칠 수 없다" 며 로그인시키지 않는다(관리 화면의 다른 탭은 계정이 필요 없다)
2. **고치는 폼은 펼친 줄 안에, 받은 차례보다 위에** — 처음엔 지난 차례(최근 20) 밑에 두었다가 찍어 보니 펼쳐도 폼이 화면 밖이었다.
   차례는 메타 → 고치기(접힌 `details`) → 명세의 이력 → 받은 차례
3. **검사는 admin 과 같은 것**(`DataSource.full_clean` → `problems_of`, 고르는 칸은 같은 표) — 틀리면 저장하지 않고 까닭을 띄운다. 바뀐 것이
   없으면 이력도 남기지 않는다. 고치면 `DataSourceChange` 에 `origin="tab"`·누가·앞뒤
4. **목록 칸(명령·산출물·근거)은 한 줄에 하나** — 근거(`jikhanjung 020`)는 띄어쓰기가 있어 빈칸으로 가를 수 없다
5. **명세의 이력은 누구에게나** — 펼친 줄에 최근 열 줄(때·어디서·누가·바뀐 칸). 밖에 연 판(`GSM_PUBLIC`)에는 로그인·고치기·admin 이 없다
6. 고치고 돌아오면(`?tab=sources&src=<id>`) 그 탭·그 줄·그 폼이 열린 채로 — 화면의 JS 가 탭과 줄을, 서버가 폼을. 알림은 Django messages
7. 모든 폼은 CSRF 를 묻는다. 탭 아래 안내를 "staff 로 로그인해 펼친 자리나 admin 에서" 로

## 2. 남긴 것

- **평문 HTTP** — 로그인 비밀번호와 세션이 평문으로 오간다. admin 과 같은 사정이고 HTTPS 는 나중에(사람). TODOs 그대로
- 로그인 시도 횟수 막기 — 연구소 망 안이고 계정이 몇이라 두지 않았다. 밖에 열 일이 생기면 HTTPS 와 함께
- 데이터소스 새로 넣기·지우기는 admin 에서 — 탭은 있는 줄을 고치기만

## 3. 확인

- 시험 여덟(`TabEdit`) — 로그인 전에는 폼이 없고 403, 틀린 비밀번호·staff 아닌 계정, staff 가 고치면 이력(누가·바뀐 칸)·돌아온 자리, 틀린 값은
  저장하지 않는다, 바뀐 것이 없으면 이력도 없다, CSRF, 밖에 연 판에는 없다, 로그아웃. 전체 통과
- 운영 사본으로 데스크톱·휴대폰을 찍어 봤다 — 로그인 폼, 펼친 줄의 고치기 폼(휴대폰은 한 줄씩), 가로 넘침 없음
