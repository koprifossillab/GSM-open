# 3D 에 PGC 경사·등고선 — 극지연구소 KPDC 는 잴 수 없었다

2026-10-05 · `feature/3d-polar` · wetherilli

새 일거리 둘째 판에서 빠진 것 — wetherilli 335 가 남긴 "PGC·KPDC 는 3031·3413 로만 받는다고 빠져 있다". 판 세션에 이것을 고른다고 알리고 했다.

## PGC (ArcticDEM·REMA) — 3857 도 그린다

- 문(`elevation.py`)이 레이어마다 제 투영(그린란드·스발바르 3413, 남극 3031)이 아니면 "받지 않는 투영" 으로 막고 있었다. 상류는 ArcGIS **ImageServer** 라
  `exportImage` 의 `imageSR` 로 다시 그려 준다 — 3857 로 한 장씩 물으니 경사·등고선 넷 모두 그림(1.4–1.9 초), 누르기(`identify`, `wkid` 3857)도 값이 온다(경사 23.6°)
- 문이 제 투영과 **3857** 을 받게 하고 `MAP3D_WMS` 에 `pgc` 를 더했다. 2D 는 그대로 제 투영으로 묻는다
- 3857 은 위도 85° 너머를 못 그려 3D 에서 극점 둘레는 빈다 — 3D 의 극지가 다 그렇다

## 극지연구소 KPDC 지도 서버 — 잴 수 없었다

`kpdcgeo.kopri.re.kr` 이 이 서버에서 이름이 풀리지 않는다(2026-10-05 11 시, `NameResolutionError`). 운영 2D 는 캐시로 보이고 있을 것이다. 살아나면 같은 꼴로
3857 GetMap 한 장씩 재고 되면 `MAP3D_WMS` 에 `kopri` 를 더한다 — 그때 3D 시험이 "빠지는 예" 로 쓰는 `kopri:lakes` 를 다른 것으로 바꾼다.

## 시험

PGC 문의 "다른 투영은 묻지 않는다" 시험을 3857 대신 4326 으로 바꿨다. 3D 목록 시험의 "빠지는 예" 는 PGC 에서 KPDC 로 옮겼다.
