# 시험이 덮지 않는 곳 — coverage 로 재고 위험한 차례로 메우기

2026-10-05 · `test/coverage-gaps` · wetherilli

판 세션이 준 일 — 오늘 붙은 상류가 많아 시험이 지나가지 않는 문·뷰가 있을 것이니, coverage 로 재서 위험한 차례(키·주소를 다루는 곳,
캐시 열쇠, 속성 풀이)로 시험을 더한다. 상류는 부르지 않는다.

## 잰 법

`coverage==7.16.2` 를 **개발 요구(`requirements-dev.txt`)에만** 더했다 — 제품 이미지에는 들지 않는다.

```
cd web && coverage run --source=viewer --omit='viewer/tests/*,viewer/migrations/*' manage.py test viewer
coverage report --sort=cover
```

병렬(`--parallel`)로 돌리면 프로세스마다 자료 파일이 갈려 합치는 손이 더 든다 — 한 줄로 돌렸다(17 분 남짓). CI 에는 넣지 않았다.
숫자가 문턱을 넘나 따지기 시작하면 시험을 숫자에 맞추게 된다. 가끔 사람이 재 보는 자로 둔다.

## 숫자

| | 시험 | 문장 | 빠진 문장 | 덮은 비율 |
|---|---|---|---|---|
| 전 | 1 912 | 27 902 | 5 147 | 81.55 % |
| 후 | 1 962 | 27 902 | 4 913 | 82.39 % |

손댄 파일만 보면 —

| 파일 | 전 | 후 |
|---|---|---|
| `gsi.py` | 46 % | 100 % |
| `jmg.py` | 56 % | 99 % |
| `nsgs.py` | 62 % | 100 % |
| `skgs.py` | 65 % | 95 % |
| `kigam.py` | 74 % | 86 % |
| `vworld.py` | 85 % | 88 % |
| `linked.py` | 85 % | 95 % |
| `tilecache.py` | 88 % | 100 % |
| `pointsets.py` | 88 % | 93 % |
| `views.py` | 85 % (빠짐 594) | 85 % (빠짐 592) |

`views.py` 는 22 줄을 새로 지났는데 20 줄이 새로 빠져 거의 그대로다. 빠진 20 줄은 해저·지열류 타일의 "캐시에 없으면 그린다" 갈래다 —
그 시험이 개발 캐시(`web/.tilecache`)에 담아 두어 **두 번째 잴 때는 캐시에서 꺼냈다.** 시험이 줄어든 것이 아니라 잰 자리가 같은 캐시를
보았다. 다음에 잴 때는 `GSM_TILE_CACHE_DIR` 를 빈 임시 디렉터리로 두고 잰다 — 그래야 전·후가 견줄 만하다.

## 무엇을 먼저 메웠나

0 % 인 것은 거의 `management/commands/build_*` 다 — 사람이 원본 zip 을 넣고 한 번 부르는 굽기 명령이라 시험의 값이 적다. 그대로 두었다.
그 다음 낮은 `era5`·`gfs`·`gmgsi`·`wind`·`ocean` 은 호스트에서만 도는 바람 굽기(numpy·ecCodes)라 컨테이너 시험이 닿지 않는 것이 맞다.

남은 것을 위험한 차례로 —

1. **키가 새지 않는가** (`test_risky_paths.py`) — 예외 문구에 URL 이 실려 오는 길(KIGAM `_get`·`probe_openapi_feature_info`, VWorld
   `_ned`)에 키가 섞인 예외를 던져 오류 글·로그에 키가 없는지 본다. 키가 없으면 상류를 아예 부르지 않는지, 개발 스위치와 속성 길
   (GeoServer)에 키를 싣지 않는지도. `kigam._get` 의 이 갈래들은 시험이 하나도 없었다
2. **연결 레이어의 문** — 읽지 못하는 주소(닫히지 않은 IPv6 괄호)·범위 밖 포트·풀리지 않는 이름·IP 가 아닌 답, 넘겨받을 곳이 빈
   302, 받다가 끊김. 남이 준 주소를 서버가 부르는 곳이라 오류 길이 곧 막는 길이다
3. **캐시 열쇠와 차례** — 열쇠에서 키가 빠지는 것은 이미 시험이 있었다(`test_tilecache`). 빠진 것은 **뷰가 차례를 지키는가**였다:
   키가 없을 때·상류가 못 줄 때 늙은 타일을 내는지, 새로 받은 것이 옛것을 덮는지, 자료를 파는 상류(`NO_STORE`)는 담지 않는지.
   `NO_STORE` 는 상수 하나를 보는 시험뿐이었다. 캐시 쪽은 읽기·쓰기·여유 재기가 실패해도 멈추지 않는지
4. **속성 풀이의 갈래** — `feature_info` 가 상류마다 제 `friendly` 를 고르는 `elif` 가 일흔을 넘는데 열여덟 갈래를 지나는 시험이
   없었다. 한 줄 빠뜨리면 날것의 열 이름(`LITHOLOGY`)이 팝업에 뜬다. 표 하나로 상류마다 그 함수가 불리는지 본다.
   `friendly` 함수 자체는 거의 다 시험이 있었다 — 빈 곳은 함수가 아니라 고르는 자리였다
5. **coverage 가 가장 낮던 문 넷** (`test_thin_doors.py`) — GSI·JMG·NSGS·SKGS. WMS 변수를 REST 로 옮기는 셈(누른 화소의 가운데)과
   이름을 상류 번호로 옮기는 것, 그림·JSON 이 아닌 것을 받으면 멈추는 것
6. **올린 파일** — 남이 준 것이라 깨진 것(읽지 못하는 글자, 빈 주소 열, features 없는 GeoJSON, 꼭짓점 상한, 옮기지 못하는 평면
   좌표)이 사람이 읽을 까닭으로 멈추거나, 일부만이면 건너뛰고 세는지

## 버린 것

- 문 일흔다섯을 하나씩 다 메우는 것 — 대부분 80 % 를 넘고, 남은 것은 같은 꼴의 "상태가 200 이 아니면 오류" 다. 넷만 본보기로 메웠다
- `views.py` 의 나머지 592 줄 — 달·화성 DEM·범례 같은 화면마다의 갈래다. 위험한 것(키·캐시·속성)은 아니라 다음 차례로 둔다
- 시험에서 진짜 개발 캐시를 쓰는 해저·지열류 시험을 임시 디렉터리로 옮기는 것 — 이 일의 몫을 넘는다. 위에 잴 때의 주의로만 적었다
