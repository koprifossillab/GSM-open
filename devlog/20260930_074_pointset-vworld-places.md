## 1. 무엇을 붙이나

한국 점마다 넷을 묻는다(`vworld.point_facts`).

| 칸 | 어디서 | 쓸모 |
|---|---|---|
| 도로명·지번 | 주소 API `getAddress` | 야장의 "채취지" 칸 |
| 읍면동 | 데이터 API `LT_C_ADEMD_INFO` | 행정구역으로 시료를 묶기 |
| 가장 가까운 단층 (m) | `LT_L_GIMSFAULT`, 20 km 안 | 단층대 시료인지 한눈에 |
| 둘레 지명 | `LT_P_NSNMSSITENM`, 2 km 안 | 토박이 지명 — 지형도에 적힌 이름으로 부를 수 있다 |

**단층과 지명은 기하를 받아 우리가 잰다.** 단층은 이름이 없고 `legend` 하나뿐이라(020) 몇 개가 걸렸는지보다
"가장 가까운 것까지 몇 m" 가 쓸모다. 점에서 선분까지의 거리를 평면 근사로 잰다 — 20 km 안이라 틀림이
1% 안쪽이고, 공간 라이브러리를 들이지 않는다(TODOs "하지 않기로 한 것"). 지명 반경은 004 의 1 km 로는
도심(대구 중구)에서 빈 곳이 많아 2 km 로 넓혔다.

2026-09-30 에 대전 가정동·대구 공평동·울릉·속초를 찍어 보니 한 점에 0.2 초 남짓이었다(넷을 한꺼번에).

## 2. 저장한다 — IBCSO 수심(070)과 반대로

070 은 수심을 저장하지 않고 부를 때마다 읽었다. 우리 디스크의 격자라 싸고, 판이 바뀌면 따라가서다.
이것은 **상류에 묻는 값**이다. 점묶음을 그릴 때마다 점마다 넷을 물으면 VWorld 호출이 수백 배로 늘고,
VWorld 가 닫히면 이미 받은 것도 사라진다. 그래서 표고(P03)처럼 한 번 받아 제 칸에 둔다 — `Point.place`
(JSON, 이주 0014). 받은 날(`at`)을 함께 적는다. 다시 누르면 덮는다.

`props` 에 넣지 않은 까닭도 표고와 같다 — 원본에 `주소` 열이 있으면 어느 것이 사람이 적은 것인지 가를 수
없다. 화면·내려받기에는 `도로명(VWorld)` 처럼 **출처를 이름에 달아** 싣고, 되살리기가 그 이름들을 떼어
제 칸으로 돌린다.

## 3. 언제 묻나

- **올리거나 찍어 저장할 때, 한국 점이 20 개 이하면 곧바로** — 대개의 야장은 이 안이다. 실패해도 점묶음은
  생긴다(둘레는 덤이다). 20 개를 넘으면 올리기가 몇 초씩 늘어서 사람이 고르게 둔다
- **📍 단추** — 점묶음 줄에 ⛰ 곁에 선다. 한국 점이 있고 VWorld 열쇠가 있을 때만. 50 개까지는 화면에서,
  넘으면 `manage.py fill_places <번호>` 로 넘긴다(⛰ 의 `fill_elevation` 과 같은 꼴). 점 사이를 0.2 초 둔다(010)
- 대한민국 둘레(`vworld.KOREA_BOX`) 밖의 점은 묻지 않는다 — VWorld 는 NOT_FOUND 만 준다. 극지·일본 점묶음에는
  단추가 서지 않는다

호출은 다른 VWorld 호출처럼 `upstream_stats` 의 `vworld` 로 센다. 스레드 안에서는 세지 않는다(`search` 와 같다 —
DB 연결이 스레드마다 생긴다). 그래서 주소 API 를 세지 않는 속(`_reverse`)을 따로 두었다.
