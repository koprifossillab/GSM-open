# 034 — 스발바르 3D: 디코드 오류, 느린 로딩, 한국 테마

2026-09-29 · sclee · v0.11.2 운영에서 스발바르 3D 를 연 사람이 셋을 짚었다 — "소스 이미지를
디코드하지 못했다", "로딩이 엄청나게 느리다", "다른 지도인데 기본 테마가 나온다".

## 1. 디코드 오류 — VWorld 는 한국 밖에서 XML 을 준다

서버가 낸 타일(dem·wms)은 모두 그림이었다. 남은 것은 브라우저가 곧장 부르는 VWorld 백지도다.
운영 열쇠로 찔러 보니 스발바르 자리에는 200 에 `application/xml`(`ExceptionReport`)을 준다.
도쿄 z10 도 그렇다. 3D 의 VWorld 소스에 `bounds`(동경 120–134°, 북위 30–44°)를 걸어 밖은 묻지
않는다.

## 2. 느린 것 — 원인이 셋이었다

1. **워커가 셋, 스레드가 없었다.** PGC 타일 한 장이 2–4 초 동안 워커를 붙잡는다. 3D 가 수십
   장을 부르면 줄이 서고 그동안 사이트 전체가 느리다. `--threads 8` 을 붙였다. 캐시에 쓰는
   임시 파일 이름에 프로세스·스레드를 넣어 같은 타일을 둘이 써도 부딪히지 않게 했다
2. **PGC 에 한 장씩 물었다.** 3D 는 이웃 타일을 곧 부르므로 4×4 네모(16 장)를 한 번에 받아
   다 담는다 — 16 장에 45 초가 5 초가 된다. 같은 네모를 여럿이 부르면 하나만 묻고 기다린다
3. **표고를 너무 촘촘히 불렀다.** 3D 는 256 px 표고 타일을 화면 줌보다 한 단계 촘촘히 부른다.
   `tileSize: 512` 로 여겨 한 단계 거칠게 부른다 — 타일 수가 4 분의 1 이다. 한 픽셀이 땅
   수 m–수십 m 라 지형에는 넉넉하다. PGC 는 z11 부터만 쓴다 — 멀리서는 AWS 로 넉넉하고
   브라우저가 곧장 받아 빠르다. 운영 기록에 z1 타일(반구 하나)까지 PGC 에 물은 것이 있었다

빈 캐시에서 스발바르를 z13 으로 열 때 55 초 → 25 초, 캐시가 찬 뒤로는 1 초다(헤드리스).
브라우저는 한 서버에 연결을 여섯만 열어, 처음 가는 자리는 여전히 몇십 초 걸린다.
자주 볼 자리는 `prewarm` 처럼 미리 받아 두는 길이 남아 있다.

## 3. 테마 — 3D 는 지역을 몰랐다

2D 는 `<html data-theme data-region>` 으로 지역마다 색을 바꾼다. 3D 는 둘 다 달지 않아 늘 먹갈색
이었다. 3D 머리의 스크립트가 저장소의 테마·글꼴·크기와 지역(2D 의 3D 단추가 `?region=` 으로
넘긴다)을 단다. 한반도 지질도 칸은 2D 처럼 한국·동아시아 밖에서 숨긴다.

**곁에서 본 것 둘.**
- 3D 는 보던 자리를 늘 한국의 열쇠(`gsm.view`)에 적었다. 스발바르 3D 에서 돌아가면 한국 탭이
  스발바르로 열렸다. 지역의 열쇠에, 메르카토르 줌이라고(`proj`) 적는다. 극지 탭은 그것을 보고
  줌을 옮겨 센다(`carryZoom`)
- **MapLibre 의 줌은 OpenLayers 보다 한 단계 작다**(512 px 기준 대 256 px 기준). 015 부터 두 화면이
  줌 숫자를 그대로 주고받아, 오갈 때마다 두 배씩 가까워지거나 멀어졌다. 넘길 때 1 을 빼고
  돌려줄 때 1 을 더한다
