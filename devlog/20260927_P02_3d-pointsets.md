# 3D 에 점묶음을 얹는다 (계획)

2026-09-27 · sclee · 015(3D 실험) 다음. **실험 기능 안에서만 한다.**

015 의 3D 는 지질도 한 장과 표고만 있다. 2026-09-27 에 사람이 실제 브라우저로
열어 보고 **돈다**고 했다(헤드리스로는 14 분 동안 못 그렸던 것). 그러면 다음
쓸모는 **내 점묶음을 지형 위에서 보는 것**이다 — 시료가 능선에 있나 골짜기에
있나, 조사 경로가 어느 비탈을 탔나. 2D 로는 등고선을 읽어야 알던 것이다.

## 1. 지금 있는 것

- 3D 는 `/GSM/3d/` 의 딴 화면이다 (`map3d.html`·`map3d.js`, 91 줄).
  도구 막대의 3D 단추는 `.labs` 라 **설정 → 실험 기능** 을 켠 사람에게만 뜬다
- 엔진은 MapLibre 4.7.1(저장소에 담았다), 표고는 AWS Terrain Tiles Terrarium
  (`maxzoom 15`), 지질도는 2D 와 같은 `wms/` 중계다
- 점묶음은 서버에 표로 있고 **`/GSM/pointsets/<id>/geojson/` 이 이미
  FeatureCollection 을 준다** — 점은 `Point`, 모양은 올린 기하 그대로,
  `properties` 에 딸린 속성과 `이름표`. 좌표는 언제나 EPSG:4326 이다
- 2D 의 점묶음 켜고 끄기는 **어디에도 남지 않는다.** 체크박스가 `ps.visible`
  을 브라우저 안에서만 바꾸고, 새로 고치면 서버의 `visible`(기본 참)로 돌아간다

**새 창구는 필요 없다.** 3D 가 목록(요약)과 GeoJSON 을 받기만 하면 된다.

## 2. 무엇을 하나

### 2.1 목록 — 서버가 요약을 싣는다

`map3d_view` 가 2D 와 똑같이 `_pointset_list()` 를 `json_script` 로 싣는다
(이름·색·점 수·선·면 수). 3D 패널에 "내 자료" 칸을 하나 두고 점묶음마다
체크박스·색 견본·이름·범위 맞추기(⊙)를 둔다. 내려받기·지우기는 두지 않는다 —
그것은 2D 의 일이고, 실험 화면에서 지우는 길을 열 까닭이 없다.

### 2.2 무엇을 켤지 — 2D 와 같은 것을 본다

**정한 것**: 켜고 끈 것을 **브라우저 저장소 `gsm.pointsets.off`**(끈 번호 목록)
에 둔다. 2D 체크박스가 쓰고 3D 가 읽고, 3D 에서 바꾸면 2D 도 따라간다.

- 끈 것을 적는 까닭 — 새로 올린 점묶음은 **켜진 채** 떠야 한다. 켠 것을 적으면
  새것이 꺼진 채로 나타난다
- 서버의 `PointSet.visible` 을 쓰지 않는 까닭 — 계정이 없는 뷰어라 한 사람이
  끄면 모두에게 꺼진다. 눈에 걸린 일은 브라우저에 둔다(설정의 "모양" 과 같다)
- 지역별로 가르지 않는다 — 점묶음은 지역을 가리지 않는다(016)
- 곁가지로 **2D 의 "새로 고치면 다 켜진다" 도 고쳐진다**

URL(`?ps=3,7`)로 넘기는 길은 링크를 남에게 건넬 때나 쓸모가 있다 — §7.

### 2.3 점 — 지형에 앉힌다, 세우지 않는다

MapLibre 는 지형을 켜면 `circle`·`symbol` 레이어를 그 자리의 표고에 놓는다.

| 방식 | 모습 | 판단 |
|---|---|---|
| `circle`, `pitch-alignment: viewport` | 2D 와 같은 둥근 점이 지면 위에 떠서 늘 정면을 본다 | **1 단계** |
| `circle`, `pitch-alignment: map` | 지면에 눌린 원. 기울이면 납작해진다 | 버린다 — 비탈에서 안 보인다 |
| 세운 표지(막대·핀) | 땅에서 솟은 기둥 | **하지 않는다** |

세운 표지를 버린 까닭: MapLibre 에는 "점에서 선 기둥" 이 없다. `fill-extrusion`
으로 점마다 작은 네모를 만들어 세우거나 three.js 사용자 레이어를 써야 하는데,
앞쪽은 꼭짓점이 점 수 × 5 로 불고 뒤쪽은 엔진을 하나 더 담는 일이다. 기둥이
정말 필요한 것은 **고도를 값으로 보여 줄 때**인데 그것은 P03(시료 고도)이 먼저다.

색은 `ps.color`, 흰 테 1.5 px — 2D 의 점과 같게 둔다. 사람이 같은 자료라고
알아봐야 한다.

### 2.4 모양 — 지형에 입힌다

`line`·`fill` 레이어는 MapLibre 가 지형 표면에 그려 입힌다(래스터와 같은 길).
면은 2D 처럼 색 25 % 로 칠하고 테두리 선을 따로 둔다. 선은 조사 경로·단면선이
대부분이라 **능선을 넘는 모습이 이 계획의 가장 큰 볼거리**다. 한 점묶음은
GeoJSON 소스 하나 + 레이어 넷(면·테·선·점)으로 간다 — `filter` 로 기하 갈래를
가른다.

### 2.5 이름표

2D 는 `LABEL_MIN_ZOOM` 부터 이름표를 단다. 3D 에서 **걸리는 것이 하나 있다 —
MapLibre 의 글자(`symbol` 의 `text-field`)는 글꼴 조각(`glyphs`, PBF)을 URL 에서
받아야 한다.** 지금 3D 스타일에는 `glyphs` 가 없고, CDN 을 쓰지 않는 집
규칙이 있다.

- 한글·한자는 `localIdeographFontFamily` 로 브라우저 글꼴이 그린다 — 조각이
  필요 없다
- 로마자·숫자(`KP-23-001` 같은 시료 번호가 대부분이다)는 조각이 있어야 한다.
  **0–255 한 조각만 만들어 `vendor/maplibre/glyphs/` 에 담는 것**이 가장 작다
  (수십 KB). 만드는 도구는 저장소 밖에서 한 번 돈다
- 대안: 이름표를 DOM(`maplibregl.Marker`)으로 단다. 수백 개까지는 괜찮지만
  지형에 가려도 보인다

1 단계는 **이름표 없이** 가고, 클릭하면 이름표가 팝업 머리에 뜬다. 2 단계에서
글꼴 조각을 정한다(§7).

### 2.6 클릭 → 속성

`map.queryRenderedFeatures(점, { layers: 점묶음 레이어들 })` 로 집고
`maplibregl.Popup` 에 2D 와 같은 모양의 표를 띄운다 — 머리는 점묶음 이름,
그 밑에 이름표, 표는 딸린 속성. 지질도 속성(GetFeatureInfo)은 이번에 하지
않는다 — 3D 에서 클릭한 화면 좌표를 지질도 픽셀로 되돌리는 셈이 지형 때문에
어긋난다. 점묶음은 벡터라 그 문제가 없다.

2D 의 속성 표 코드(`map.js` 의 IIFE 안)는 가져다 쓸 수 없다. 30 줄 남짓을
`map3d.js` 에 따로 둔다 — 실험 화면이 본 화면의 속을 끌어다 쓰게 하지 않는다.

### 2.7 영어판

새 글(“내 자료”, “이 자료로 범위를 맞춘다” …)은 같은 커밋에 `i18n.EN` 을
채운다. **`map3d.html` 에는 지금 `i18n-data` 가 없어** JS 가 `T()` 를 쓸 수
없다. 2D 처럼 싣고 `T()` 몇 줄을 둔다. **`test_i18n` 은 지금 `map.js` 만
긁는다**(템플릿은 `map3d.html` 까지 본다) — `map3d.js` 도 긁게 한 줄 고친다.
안 고치면 3D 의 영어가 빠져도 시험이 모른다.

## 3. 지역 — 3D 는 메르카토르 하나다

MapLibre 는 **Web Mercator(3857) 뿐이다.** 2D 는 이번 판부터 극지를 EPSG:3413
(그린란드)·3031(남극)으로 그리지만 3D 는 그럴 수 없다. 뜻하는 것:

- **점묶음 자체는 문제가 없다** — 위경도로 들고 있으니 어느 화면이든 그대로 얹힌다
- 메르카토르는 **남북 85.05° 에서 끊긴다.** 그린란드(60–83°N)는 부푼 채로
  보이고, 남극은 남위 85° 안쪽이 아예 없다. 세종·장보고기지(62°·74°S)는 보인다
- 표고도 문제다 — SRTM 은 60°N–56°S 만 덮는다. 그 밖에서 Terrarium 이 무엇을
  섞어 주는지(ETOPO1·GMTED 같은 거친 판인지) **확인하지 않았다**
- 지금 3D 는 **한국 자리(`gsm.view`)만 읽는다.** 그린란드 탭에서 3D 를 눌러도
  한국이 열린다

**정한 것**: 3D 는 **한국 중심** 그대로 둔다. 점묶음은 지역을 가리지 않고 다
싣되, 범위 맞추기(⊙)로 극지 점묶음에 가면 그대로 간다 — 부푼 모습과 거친
지형을 감추지 않는다. 극지 3D 를 제대로 하는 것은 이 계획의 일이 아니다
(극지 표고는 P03·TODOs, P01 스발바르도 같은 사정이다).

## 4. 크기 한도

- 올리기가 이미 막는다 — 모양 하나 5 만, 점묶음 하나 30 만 꼭짓점
  (`pointsets.py`). 점은 한도가 없다
- MapLibre 의 GeoJSON 소스는 작업자 스레드에서 잘라 그린다. 점 몇 만은 괜찮다
- 걸리는 것은 **지형이 켜진 채 레이어가 늘어나는 것**이다 — 점묶음 × 4 레이어.
  점묶음이 스물이면 여든이다. 1 단계는 그대로 가고, 느리면 **켜진 점묶음만
  소스를 만든다**(끈 것은 받지도 않는다)
- 켜진 점이 모두 2 만을 넘으면 패널에 한 줄 띄운다 — 막지는 않는다

## 5. 순서

1. **2D**: 켜고 끈 것을 `gsm.pointsets.off` 에 남긴다. 3D 없이도 쓸모 있는 고침이다
2. **서버**: `map3d_view` 가 점묶음 요약과 `i18n-data` 를 싣는다
3. **3D**: 패널의 "내 자료" + 점묶음마다 소스·레이어(점·선·면) + 범위 맞추기
4. **3D**: 클릭 → 속성 팝업
5. **3D**: 이름표 — §7 의 답을 받고

1~4 를 한 판(v0.6.x)으로, 5 는 따로 낸다. 모두 3D 안이라 실험 딱지는 그대로다.

## 6. 확인하는 법

헤드리스는 지형을 못 그리므로(015) **눈으로 보는 것이 본 확인이다.** 순서:

- 시험 점묶음 하나 — 설악산 대청봉(38.119, 128.465 — 3D 의 기본 자리)과
  둘레 골짜기 점 몇, 오색 → 대청봉 등산로 선 하나, 봉우리를 두른 면 하나
- 본다: 점이 봉우리 **위에** 앉나(땅속에 묻히거나 떠 있지 않나), 지형 과장을
  ×1 ↔ ×4 로 밀어도 따라가나, 선이 능선을 넘으며 끊기지 않나, 면이 비탈을 덮나
- 2D 에서 끈 점묶음이 3D 에서 꺼져 있나, 3D 에서 켜고 돌아오면 2D 도 켜졌나
- 점을 클릭 → 이름표와 속성이 2D 팝업과 같나. `?lang=en` 으로도
- 서버 쪽 시험: `map3d_view` 가 점묶음 요약을 싣는지(`test_views` 한 줄),
  `test_i18n` 이 새 글을 잡는지

## 7. 사람에게 묻는 것

1. **이름표 글꼴 조각** — 로마자 조각 하나를 저장소에 담는가(수십 KB), 아니면
   이름표를 DOM 으로 다는가, 아니면 3D 에서는 이름표 없이 클릭으로만 보는가
2. **URL 로 넘기기** — `3d/?ps=3,7` 처럼 링크에 점묶음을 싣는 길이 필요한가.
   남에게 "이 자료를 3D 로 봐라" 고 건넬 일이 있으면 둔다
3. **극지에서 3D 단추** — 그린란드·남극 탭에서는 3D 단추를 숨기는가, 아니면
   지금처럼 한국으로 여는가, 아니면 그 지역의 자리로 여는가(메르카토르로)
4. **지질도 속성도 3D 에서 읽고 싶은가** — 하면 클릭한 지면 좌표
   (`map.unproject` 는 지형을 안다)로 GetFeatureInfo 를 따로 묻는 길이다.
   이번에는 뺐다

## 8. 버린 것

- **세운 표지(기둥)** — §2.3. 고도를 값으로 보이는 일은 P03 뒤에
- **점을 표고만큼 띄워 그리기** — 점에 고도가 없다(P03 전). 있더라도 GPS 고도와
  DEM 고도가 어긋나면 점이 땅에 묻히거나 뜬다 — 지형에 붙이는 편이 정직하다
- **3D 에서 점묶음 올리기·고치기** — 2D 가 한다. 실험 화면은 보기만 한다
- **2D 의 OpenLayers 벡터를 3D 로 넘기기** — 두 화면은 딴 페이지다. 서버의
  GeoJSON 이 두 화면의 공통 원본이다
