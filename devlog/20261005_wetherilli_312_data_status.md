# 구운 자료의 나이 — data_status

2026-10-05 · `feature/data-status` · wetherilli

판 세션이 준 일 — 굽는 명령(`build_*`)·모으는 명령(`fetch_*`)이 하루에 열 남짓 늘었다. 운영의 `<DB 옆>` 아래 파일마다 있는지·크기·만든 날·원본 판을
한 표로 내는 `manage.py data_status`. healthz 에는 "있어야 하는데 없는 파일" 수만. 관리 화면에 붙일지는 상류 응답 시간 칸(wetherilli 295) 꼴을 따른다.
운영은 읽기만.

## 표는 손으로 적는다

파일 목록을 폴더를 훑어 지을 수도 있었지만, 그러면 "있어야 하는데 없는 것" 을 말할 수 없다 — 없는 파일은 훑어도 안 보인다. 그래서 `datastatus.ITEMS`
에 **파일과 그것을 만드는 명령**을 한 줄씩 적었다(39 줄). 새로 굽는 파일을 더하면 거기 한 줄 — CLAUDE.md 의 "파일을 받아" 절에 그렇게 적었다.
경로는 설정 이름(`EARTH_DIR` 따위)과 그 안의 이름으로 적어 화면에 절대 경로가 나가지 않는다.

- **원본 판은 이미 있는 것에서** — 지열류·응력·광상·빙하·PBDB·지진·Neotoma 의 sqlite 가 `meta` 표에 `built`·`source` 를 적어 두었고, GVP·극지연구소
  JSON 은 머리에 `source`·`fetched` 를 둔다. 앞 4 KB 만 읽는다. 바람·해류는 `index.json` 의 첫·끝 시점, GeoMAP 은 파일 이름의 `v2022_08`.
  달·화성·수성·카리브의 sqlite 는 판을 적어 두지 않아 칸이 빈다 — 굽는 쪽을 고치는 것은 이 일 밖이다
- **폴더는 위 칸만** — 바람(3 GB)·IBCSO 타일을 다 훑지 않는다. 칸 수와 가장 새 칸의 고친 때, 그 이름이 날짜(`20260930`)면 판으로
- **열쇠 파일은 적지 않는다** — `kigam_key`·`vworld_key`·`geus_whoami`·`secret_key`. 있다는 것도 관리 화면에 내지 않는다
- 저장소의 `data/` 씨앗은 판과 함께 오므로 적지 않았다
- 연구실 내부용(한반도 지질도·geo3al)은 밖에 연 판에서 "있어야 하는" 것에서 뺀다
- 대만 열린자료(305)는 그 판이 들어온 뒤에만 줄이 선다(`TAIWAN_OPEN_DIR` 가 있으면)

## healthz 는 수만, 상태는 그대로

`{"data": {"items": 39, "missing": 0}}`. **degraded 로 바꾸지 않았다** — 파일 하나가 없으면 그 레이어 자리에 안내가 뜰 뿐 뷰어는 돈다. healthz 는
`stat` 만 한다(sqlite 를 열지 않는다) — 가볍게 둔다는 healthz 의 약속 그대로다. 표의 셈과 가벼운 셈이 같은지는 시험이 본다.

## 관리 화면

"구운 자료" 칸 하나 — 상류 응답 시간처럼 서버가 그리고 읽기만 한다. 있어야 하는데 없는 줄은 붉게. 열 이름 "판" 은 이미 "Plate"(판 구조)로
옮겨 쓰고 있어 **"원본 판"** 으로 했다 — 한 낱말이 두 뜻을 겸하지 않게.
