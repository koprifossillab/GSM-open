# 원본은 날짜 폴더에 바뀐 판만, 최근 세 벌만 (P02 4 단계)

2026-10-06 · `feature/raw-prune` · jikhanjung

jikhanjung P02 의 4 단계. kigam50k 가 혼자 쓰던 "원본을 날짜 폴더에, 같으면 새 폴더 없이" 의 틀을 뽑고, 옛 벌을 지우는 명령을 세웠다.
1–3 단계에서 계획만 하고 화면에 안 올린 둘(씨앗과 다른 줄, 상류 판·바뀐 수)도 같이 올렸다.

## 1. 무엇을 정했나

1. **틀은 `rawstore.py` 로** — 계획은 `sources.save_raw` 였지만 `sources.py` 는 명세를 읽고 검사하는 곳이라 원본 파일을 다루는 것을
   섞지 않았다. 문이 아니다 — 문이 받은 본문을 넘긴다
   - `save(자리, 파일들, meta, now)` — 파일마다 풀린 본문의 sha256 이 가장 새 폴더의 매니페스트와 **모두 같으면** 새 폴더 없이 `checked` 만.
     다르면 `.<날짜>.part` 에 적고 이름을 바꾼다. 기록 표에 `raw_path`·`raw_sha256`(파일 sha 를 이은 것의 sha)·`changed`
   - **`changed` 는 바뀐 파일의 수**다 — 같으면 0, 앞 판이 없으면 모두. kigam50k 는 2 단계에서 "바뀌었다" 의 1 만 적었다
   - 매니페스트의 칸 이름은 부르는 쪽이 정한다(kigam50k 는 `layers` 그대로) — 이미 받아 둔 판의 매니페스트와 견주어야 해서
2. **`manage.py prune_raw`** — 명세의 `raw` 가 날짜 폴더인 데이터소스마다 최근 3 벌(`--keep`)만. **사람이 부른다**(cron 에 두지 않는다 —
   지우는 일이다). `--dry-run` 이 먼저, `--source` 로 하나만
   - 이름이 여덟 자리 숫자인 폴더만 센다 — `.part`·다른 폴더는 건드리지 않는다. **가장 새 것은 `--keep 0` 이어도 남긴다**(읽는 쪽이 그것을 본다)
   - 명세의 `raw` 는 `<DB 옆>` 아래 자리로 적었지만, 첫 마디가 설정의 `<이름>_DIR` 이면 그 자리를 따른다(`kigam50k/raw` → `KIGAM50K_DIR/raw`) —
     운영이 자리를 옮겨도 맞게
   - 지금 운영에서 날짜 폴더인 것은 kigam50k 하나(1 벌)다 — `--dry-run` 으로 확인했다
3. **날짜 없이 덮어쓰는 원본의 sha** — PBDB 는 **받는 대로 셈한다**(`pbdb.download(digest=…)`, 150 MB 를 다시 읽지 않게 — #369 검토),
   지진(18 MB)·Neotoma(24 MB)는 받은 뒤 파일째 셈한다. 받지 않고 굽기만 하면(`--csv`) 없다. 그 원본을 날짜 폴더로 옮기는 것은 계획대로
   적재(②) 때
4. **화면 — 씨앗과 다른 줄** (P02 §9) — 운영 명세의 줄이 씨앗의 같은 id 와 다르면 이름 칸에 "씨앗과 다름 · 다른 칸" 을, 탭 머리에 수를.
   씨앗은 있는 id 를 덮지 않으므로 씨앗의 고침이 운영에 안 닿는다 — 옮길지는 사람이 정한다. 운영 명세를 읽었을 때만 견준다. healthz 는 보지 않는다
5. **화면 — 상류 판·바뀐 수** (P02 §6) — 결과 칸과 지난 차례에 "상류 판 …" 과 "앞 판과 같다 / 바뀐 것 n". **"판" 한 낱말은 이미 "Plate"
   (지판)로 옮기고 있어** 따로 "상류 판"(upstream version)으로 적었다 — 한 낱말이 두 뜻을 겸하지 않게

## 2. 버린 것

- **`prune_raw` 를 받는 일 끝에서 저절로** — 받는 일이 지우면 실수 하나로 원본이 사라진다. 지우기는 사람이 본 뒤에
- **PBDB 를 받은 뒤 파일째 셈하기** — 2 단계 검토가 짚은 그 150 MB 다시 읽기
- `changed` 를 행(산지·지진) 수로 — 원본을 행으로 가르는 것은 적재(②)의 일이다

## 3. 확인

- `test_rawstore` 10 개 — 같으면 새 폴더 없이·바뀌면 새 폴더와 바뀐 수·같은 날 두 번째, 지우기(`--dry-run`·최근 몇 벌·가장 새 것·날짜 폴더 아닌 것),
  명령이 명세의 날짜 폴더만 본다, 자리 옮기기, PBDB 를 받는 대로 셈하기, 화면의 상류 판·바뀐 수·씨앗과 다른 줄(영어판까지)
- kigam50k 의 받기 시험(같으면 새 폴더 없이·바뀌면 새 폴더)은 틀을 옮긴 뒤에도 그대로 지난다. 전체 2 096 개 통과
- 운영 파일을 읽기만 하며 `prune_raw --dry-run` — kigam50k 1 벌, 지울 것 0

## 검토 뒤에 고친 것 (#379, koprifossillab 의 검토, 2026-10-07)

1. **`manifest.json` 이 든 날짜 폴더만 판으로 센다** — 이름만 보면 구운 산출물도 날짜 폴더다(ERA5 의 `wind/era5/20050601/`, 944 칸).
   명세의 `raw` 를 잘못 적으면 `prune_raw` 한 번에 941 일이 지워진다. 명세는 손으로(곧 관리 화면에서) 고치는 것이라 실수 한 번이 큰
   지우기가 되지 않게 했다. 운영의 kigam50k 판(20260930)은 매니페스트가 있어 그대로 센다
2. **매니페스트를 바꿔치기로 적는다** — 같은 판일 때 가장 새 판의 매니페스트를 고쳐 쓰다 끊기면 그것이 깨졌다
3. `save()` 의 인자 `label` 을 `where` 로 — 같은 모듈의 `label()` 과 이름이 겹쳤다. 주지 않으면 `label(folder)`(`<DB 옆>` 아래 이름)이라 절대 경로가
   기록 표에 들어가지 않는다
4. **확인한 때는 최근 30 개만**(`CHECKED_KEEP`), 모두 몇 번이었는지는 `checked_count`
