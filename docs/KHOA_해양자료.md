**[확인]** 은 요청을 보내 응답을 본 것, **[추정]** 은 문서·응답에서 읽은 것이다. 레이어마다 개수·열을 한 번씩, 1 초 간격으로 물었다.

## 요약

- 그 페이지는 **바다누리 해양정보 서비스의 "해양정보 다운로드"** 다 — 조위관측소·해양관측소·부이·해양과학기지의
  월보·년보·1시간 자료(txt)를 고르는 화면이라 지도 자료가 아니라 시계열이다
- 화면 뒤의 **GeoServer 프록시가 키 없이 열려 있다** — `geotwo_postgis:` 레이어 289 개 **[확인]**. 문서에 없는 주소다
- **이용 조건이 둘로 갈린다** — 바다누리 OPEN API 의 표시는 **공공누리 제4유형**(상업 금지·변경 금지),
  공공데이터포털에 올린 같은 기관의 API 는 **제1유형** 이나 "제한 없음" 이다
- **바다누리 자체 OPEN API 는 닫혔다** — 공공데이터포털(`apis.data.go.kr/1192136/…`)로 옮겼다
- 지질 뷰어에 쓸 것은 **수심**(등심선·150 m 격자)과 **기본수준점·영해선** 정도다. 289 개 가운데 열하나만 추렸다

GeoServer 레이어에는 공공누리 표시가 따로 없다. 저작권 정책을 보수적으로 읽으면 **협의 대상**이고, 화면 쪽 표시를 따르면
제4유형(비상업)이다 — 브라질 SGB·페루 INGEMMET 처럼 **정적 판에 싣지 않는 쪽**에 둔다. 같은 자료가 공공데이터포털에 제1유형으로
있으면(기본수준점·조화상수·수심) 그쪽을 쓴다.

페이지 HTML 에 KHOA 배경지도 키(`otmsBasemapApi.do?ServiceKey=…`)가 박혀 있다 — **그쪽 키이므로 쓰지 않는다.**

## API

- 바다누리 OPEN API 링크(`/oceangrid/khoa/takepart/openapi/openApiObsTideHarDataInfo.do`)는 **404**, `/api/oceangrid/…` 는 `503.html` 로 돌린다 **[확인]**

**활용신청·응답 꼴은 아직 보지 않았다.**

## GeoServer — 289 개에서 추린 것

주소: `https://www.khoa.go.kr/oceangrid/cmm/proxyRun.do?call=wms|wfs` (워크스페이스 `geotwo_postgis:`)

- **WFS `GetCapabilities` 는 정상**, **WMS `GetCapabilities` 는 상류에서 깨진다** — 레이어군 `og_dept_gm` 의 범위를 못 써서 레이어 목록 앞에서 끊긴다 **[확인]**
- WMS `GetMap` 은 된다 — `og_dept_as_kr1` 을 3857 로 받으니 0·20·50·100 m 등심선이 그려졌다 **[확인]**
- WFS `GetFeature` 는 GeoJSON(4326)으로 곧장 온다 **[확인]**
- User-Agent `GSM/0.1` 로 막히지 않았다

## 권하는 길

1. **수심은 공공데이터포털 API(제1유형)** 로 — 키를 신청하고 응답 꼴을 본 뒤 150 m 격자를 받아 굽는다. 정적 판에도 실을 수 있다
2. **등심선(`og_dept_as_*`)·영해선은 GeoServer 의 WMS 타일**로 — KIGAM 의 `/mgeo/geoserver` 처럼 "문서에 없는 주소" 라고 적고,
   제4유형으로 보고 **정적 판에는 싣지 않는다.** 조건을 사람이 KHOA(051-400-4377)에 물어 정하기 전까지
3. 기본수준점·조화상수는 포털 API 로 받는다 — GeoServer 의 같은 레이어는 쓰지 않는다

새 상류가 되면 문은 `khoa.py` 하나, 상류 이름 `khoa`. 한국 탭(3857)의 레이어군 "해양" 쯤.
