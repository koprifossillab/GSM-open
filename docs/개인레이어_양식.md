# 개인 레이어 양식 v1

관리 화면(`/GSM/manage/`)의 **개인 레이어 반입**이 받는 자료의 꼴이다 (wetherilli P08·118).
반입한 것은 **이 브라우저에만** 남고 서버로 가지 않는다. 지도의 "개인 레이어" 블록에 뜬다.

- 양식 이름은 `gsm-personal-layer`, 판은 `1` 이다
- 글자는 **JSON**(GeoJSON 에 `gsm` 머리를 더한 것)과 **CSV** 두 가지다. 같은 자료는 어느 쪽으로 적어도
  같은 레이어가 된다 — 관리 화면에서 한쪽으로 받아 다른 쪽으로 내려받을 수 있다
- **점·선·면은 좌표 값의 꼴이 정한다.** 따로 적는 칸이 없다
- 한 레이어에는 한 가지만 담는다 — **섞여 오면 모양마다 갈라 레이어 여럿으로 만든다**("이름 — 점"·"이름 — 선"·"이름 — 면").
  좌표가 없는 행은 맨 앞 갈래(점이 있으면 점)에 둔다 (wetherilli 126)
- 좌표는 **WGS84 십진도**(경도·위도)뿐이다. 평면 좌표계는 받지 않는다 — 옮겨서 넣는다

| 좌표 값의 꼴 | JSON (`geometry.type`) | CSV | 레이어 |
|---|---|---|---|
| 경위도 한 쌍 | `Point` | `lon`·`lat` 두 칸, 또는 `geometry` 칸의 `POINT (경도 위도)` | 점 |
| 경위도 여럿 | `MultiPoint` | `geometry` 칸의 `MULTIPOINT (…)` | 점 |
| 꺾은선 | `LineString` | `geometry` 칸의 `LINESTRING (…)` | 선 |
| 꺾은선 여럿 | `MultiLineString` | `geometry` 칸의 `MULTILINESTRING ((…))` | 선 |
| 고리 | `Polygon` | `geometry` 칸의 `POLYGON ((…))` | 면 |
| 고리 여럿 | `MultiPolygon` | `geometry` 칸의 `MULTIPOLYGON (((…)))` | 면 |

선(`LineString`)은 2026-10-01 에 더했다(wetherilli 126). 판 번호는 그대로 `1` 이다 — 전에 받던 것은 다 그대로 받는다.

## 머리 — 레이어 하나에 대한 것

| 열쇠 | 반드시 | 뜻 |
|---|---|---|
| `format` | | `gsm-personal-layer` |
| `version` | | `1` |
| `name` | 권함 | 레이어 이름. 없으면 파일 이름을 쓴다 |
| `description` | | 설명 |
| `source` | 권함 | 어디서 온 자료인가 (사람이 읽는 글) |
| `source_url` | | 원본의 주소 |
| `license` | | 이용 조건 |
| `created` | | 만든 날 (`YYYY-MM-DD`) |
| `label` | | 지도에 이름표로 적을 열의 `key` |
| `color` | | 점·면의 색 `#rrggbb` |
| `columns` | 권함 | 열 설명의 목록 — 아래 |

열 설명은 `key`(속성 이름)·`label`(화면에 보일 이름)·`type`·`note`(설명) 넷이다. `type` 은
`string`·`integer`·`number` 셋이다. 적지 않은 열은 `string` 으로 본다. 그 밖의 열쇠는 그대로 들고 다니고
내려받을 때 다시 적는다 — 버리지 않는다.

**쓰지 않는 열 이름** — `id`·`lon`·`lat`·`geometry` 는 좌표와 번호의 자리라 속성 이름으로 쓰지 않는다.

빈 값은 JSON 은 `null`, CSV 는 빈 칸이다. 둘은 같은 것으로 읽는다.

## JSON

[GeoJSON](https://datatracker.ietf.org/doc/html/rfc7946) `FeatureCollection` 에 `gsm` 머리를 더한다.
QGIS 같은 프로그램은 `gsm` 을 모르고 넘기므로 그대로 열린다.

```json
{
  "type": "FeatureCollection",
  "gsm": {
    "format": "gsm-personal-layer",
    "version": 1,
    "name": "북한 화석 산출 기록",
    "source": "phyloserver nkfcluster 전체목록",
    "label": "species_name",
    "columns": [
      {"key": "species_name", "label": "종명", "type": "string"},
      {"key": "coord_n", "label": "좌표를 낸 점 수", "type": "integer", "note": "평균에 든 occ2·occ6 의 수"}
    ]
  },
  "features": [
    {"type": "Feature", "id": "4878",
     "geometry": {"type": "Point", "coordinates": [125.77, 38.67]},
     "properties": {"species_name": "Acodus firmus", "coord_n": 12}}
  ]
}
```

- `geometry` 는 `null` 일 수 있다 — 좌표를 모르는 행도 버리지 않고 들고 다닌다. 지도에는 안 뜬다
- `id` 는 원본의 번호다. 있으면 내려받을 때 그대로 나간다

## CSV

UTF-8 이 원칙이고 BOM 이 있어도 된다. 한국어 엑셀이 저장한 EUC-KR(CP949)도 읽는다. 구분은 쉼표, 따옴표는
RFC 4180 대로다.

머리는 **맨 위의 `#` 줄**에 `#열쇠: 값` 으로 적는다. 열 설명은 `#column: key | label | type | note` 를
열마다 한 줄. 그다음 줄이 열 이름(머리줄)이다.

```csv
#format: gsm-personal-layer
#version: 1
#name: 북한 화석 산출 기록
#source: phyloserver nkfcluster 전체목록
#label: species_name
#column: species_name | 종명 | string
#column: coord_n | 좌표를 낸 점 수 | integer | 평균에 든 occ2·occ6 의 수
id,lon,lat,species_name,coord_n
4878,125.77,38.67,Acodus firmus,12
4801,,,Acontiodus arcuatus,
```

- 점은 `lon`·`lat` 두 칸이다. 둘 다 비면 좌표를 모르는 행이다
- 면은 `geometry` 칸에 WKT 를 적는다 (QGIS 가 CSV 로 내보낼 때의 꼴이다). `geometry` 칸이 있으면 `lon`·`lat` 은
  여느 속성으로 읽는다
- `#` 머리가 없어도 읽는다 — 그때는 이름·열 설명 없이 모든 열을 글자로 받는다
- 좌표 칸 이름으로 `경도`·`위도`·`longitude`·`latitude`·`x`·`y` 도 알아듣지만 경고가 뜬다. 양식은 `lon`·`lat` 이다

## 받을 때 보는 것

반입 화면은 저장하기 전에 다음을 보여 준다.

- 점/면, 행 수, 그 가운데 지도에 뜨는 수와 좌표가 없는 수
- 열 목록과 형식
- 읽지 못한 줄 — 줄 번호와 까닭. 좌표를 못 읽은 행도 속성은 남긴다
- 경고 — 머리가 없다, 좌표 칸 이름이 양식과 다르다 따위

## 저장

브라우저의 IndexedDB(`gsm-personal`)에 둔다. 같은 브라우저·같은 주소로 다시 들어오면 남아 있고, 다른 브라우저나
다른 기계에는 없다. 브라우저가 공간이 모자랄 때 지울 수 있어 관리 화면에서 "지우지 말라" 를 청할 수 있다
(`navigator.storage.persist`). 사생활 모드에서는 창을 닫으면 사라진다.

## 연결 — 남의 API 로 받기 (wetherilli P09·122)

관리 화면의 **API 로 잇기** 에 주소와 인증키를 넣으면, 그 레이어는 **지도를 열 때마다 새로 받는다.** 받지 못하면 마지막으로
받은 것을 그리고 "받지 못해 옛것" 이라 적는다. 주소와 키는 그 브라우저(IndexedDB)에만 있고, JSON·CSV 로 내려받을 때도
실리지 않는다.

### 상대 사이트가 지킬 것

- `GET <주소>` 가 이 양식 v1 의 JSON 또는 CSV 를 그대로 준다. 200 이 아니면 받지 못한 것으로 본다(401·403 은 "인증키를 본다")
- 사람이 **API 의 목차 주소**를 넣어도 된다 — 받은 JSON 에 `endpoints`(또는 `links`)로 같은 호스트의 `url` 이 적혀 있으면 차례로
  받아 보고, 읽히는 것을 연결의 주소로 바꿔 적는다(자리표 `{id}` 가 든 것은 뺀다, wetherilli 129). 피처 하나(`Feature`)도 받는다
- 인증키는 넷 가운데 하나로 받는다 — 연결할 때 사람이 고른다

| 방식 | 보내는 꼴 |
|---|---|
| 없음 | 키 없이 |
| Bearer | `Authorization: Bearer <키>` |
| 머리 | `<이름>: <키>` (예: `X-API-Key`) |
| 주소 | `<주소>?<이름>=<키>` |

- **CORS 를 열어 주면 좋다** — `Access-Control-Allow-Origin` 에 우리 뷰어의 주소(또는 `*`), 머리로 키를 받으면
  `Access-Control-Allow-Headers` 에 그 이름(`Authorization`·`X-API-Key`). 열면 브라우저가 곧장 받고 우리 서버는 끼지 않는다
- 열지 않으면 우리 서버(`/GSM/linked/fetch/`)가 대신 받는다. 이때 상대에게는 같은 요청이 두 번 갈 수 있다 — 브라우저가
  곧장 해 보다 막힌 것 한 번, 서버가 받은 것 한 번
- 넘겨주기(3xx)는 세 번까지 따른다. 다른 호스트로 넘어가면 키를 싣지 않는다
- 20 MB · 20 초 안에 끝나야 한다
- IP 로 막는 API 는 **우리 서버의 IP(극지연구소)를 열어 주면** 서버 길로 받는다 — 보는 사람의 브라우저는 곧장 못 받는다.
  FSIS(`https://kofhin.psok.or.kr/fsis/api/v1/sites/`)가 그렇다. 인증 방식은 "없음"

### 우리 서버가 대신 받을 때 막는 것

- http·https 만, 포트는 80·443 과 1024 위만
- **연구실 망·자기 자신(사설·루프백·링크로컬 주소)은 부르지 않는다.** 연구실 안의 API 를 잇고 싶으면 운영자가
  `GSM_LINKED_ALLOW`(또는 `<DB 옆>/linked_allow`)에 그 호스트를 적는다
- 한 사람이 1 분에 30 번까지. 밖에 연 뷰어(`GSM_PUBLIC`)에서는 이 길을 닫는다 — 그때는 상대가 CORS 를 열어야 한다
- 주소와 키를 적지 않는다. 로그에 남는 주소는 키 자리를 지운다
